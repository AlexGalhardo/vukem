# Changelog rules

- `CHANGELOG.md` follows Keep a Changelog 1.1.0; each release section is generated by `internal/tools/release` (git-cliff) when a PLAN.md task group is released.
- One release per task group: Prototype `v0.0.N`, ALPHA and BETA `v0.N.0` (BETA closes with `v1.0.0-beta.1`); run `task release -- vX.Y.Z` (ci:full, changelog, tag, push, GitHub release).
- Never edit released sections by hand; fix the commit history or `.config/cliff.toml` instead.
- Sections: Added, Changed, Deprecated, Removed, Fixed, Security. `[Unreleased]` always exists.
- Versions follow SemVer with Go tags `vX.Y.Z`; never move or delete a pushed tag (use `retract`).
