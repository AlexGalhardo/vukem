O Vukem é um framework web para a [linguagem de programação Go](https://go.dev). Ele ajuda você a construir **sites, APIs REST e aplicações full-stack** sem ligar cada peça na mão: rotas, validação, uma camada de banco de dados com migrations, autenticação, views, jobs em segundo plano, testes e uma ferramenta de linha de comando que gera código para você.

Você vai aprender:

- o que um framework web faz e o que o Vukem acrescenta ao Go
- as ideias que moldam o Vukem (biblioteca padrão em primeiro lugar, sem mágica, tipado de ponta a ponta)
- como é um handler do Vukem
- quais recursos já estão disponíveis
- para onde ir depois, de acordo com o que você já sabe

## O que um framework web faz

Quando você abre uma página no navegador, ele envia uma **requisição** (request) para um servidor ("me dê `/tasks`"). O servidor executa algum código e devolve uma **resposta** (response): uma página HTML, um JSON, uma imagem. Um framework web é o conjunto de ferramentas que torna agradável escrever esse código do servidor.

Pense em um restaurante. O cliente (o navegador) faz o pedido pelo cardápio. O garçom (o <Term tip="A parte do framework que olha a URL e o método da requisição e decide qual função vai respondê-la.">router</Term>) leva o pedido ao cozinheiro certo. O cozinheiro (o seu <Term tip="Uma função que recebe uma requisição e escreve uma resposta. No Vukem ela tem a forma func(c *web.Ctx) error.">handler</Term>) prepara o prato. A segurança na porta (o <Term tip="Código que roda antes e depois dos handlers, em toda requisição ou em um grupo de rotas: logs, sessões, cabeçalhos de segurança.">middleware</Term>) confere todo mundo que entra.

O Go já traz a cozinha básica na biblioteca padrão: o pacote [`net/http`](https://pkg.go.dev/net/http) sabe escutar requisições e enviar respostas. O Vukem mantém essa cozinha e acrescenta o resto do restaurante:

| Você precisa… | A biblioteca padrão do Go oferece | O Vukem acrescenta |
| --- | --- | --- |
| Ligar URLs a código | Padrões do `http.ServeMux` | Rotas nomeadas, grupos, resource controllers, geração de URLs |
| Ler e conferir a entrada | `r.FormValue`, `encoding/json` | `web.Parse` com schemas `z` no estilo Zod e erros por campo |
| Falar com um banco de dados | `database/sql` | Conexões, um ORM genérico, migrations, factories, seeders |
| Renderizar páginas | `html/template` | Layouts, partials, fragmentos htmx, assets do Vite, Inertia |
| Manter usuários logados | Cookies | Sessões, proteção CSRF, guards, tokens de API, 2FA |
| Executar coisas depois | Goroutines | Filas, um agendador, eventos |
| Testar tudo isso | `net/http/httptest` | `vukemtest`: um cliente em processo com asserções fluentes |

## Por que o Vukem

- **Biblioteca padrão em primeiro lugar.** Handlers e middlewares são `net/http` puro. Qualquer `http.Handler` funciona dentro de uma app Vukem, e uma app Vukem é um `http.Handler`.
- **Sem mágica.** Sem variáveis globais, sem registro via `init()`, sem injeção de dependência baseada em reflection. Os geradores escrevem arquivos Go comuns, que são seus e que você consegue ler.
- **Tipado de ponta a ponta.** A configuração é carregada em structs tipadas. As rotas nomeadas são verificadas quando a app inicia. Toda entrada é convertida em tipos Go por um schema `z` antes de chegar ao seu código.
- **Tudo incluído, mas opcional.** O SQLite funciona de imediato com um driver em Go puro (sem compilador C). PostgreSQL, MySQL, Redis, MongoDB, S3 e WebSockets ficam em módulos de driver separados, então você só baixa o que usa.
- **APIs como cidadãs de primeira classe.** Os erros viram problem details da [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457), e grupos de rotas só com JSON, CORS e limites de tamanho do corpo já vêm embutidos.
- **Seguro por padrão.** Cabeçalhos de segurança com nonces de CSP, CORS que nega tudo por padrão, arquivos estáticos protegidos contra path traversal e verificações na inicialização que falham de forma segura, mapeados para o [OWASP Top 10:2025](/docs/security/overview).

<Quote source="https://go.dev/doc/effective_go" author="Effective Go" title="go.dev/doc/effective_go">
A straightforward translation of a C++ or Java program into Go is unlikely to produce a satisfactory result.
</Quote>

Em outras palavras: traduzir um programa C++ ou Java diretamente para Go dificilmente dá um bom resultado. O Vukem segue esse conselho: ele empresta a produtividade do [Laravel](https://laravel.com) e do [AdonisJS](https://adonisjs.com), mas o código que você escreve é Go idiomático.

## Um gostinho

Um handler é uma função que recebe um `*web.Ctx` (a requisição e a resposta, juntas) e retorna um `error`. Quando ele retorna um erro, um handler de erros central o transforma na resposta certa para quem pediu: uma página HTML para um navegador, um redirecionamento com os erros do formulário guardados na sessão, ou problem+json para um cliente de API.

```go title="app/controllers/task_controller.go"
// Edit shows the edit form: GET /tasks/{task}/edit.
func (tc *TaskController) Edit(c *web.Ctx) error {
	// A non-numeric id such as /tasks/abc/edit becomes 404.
	id, err := c.ParamInt("task")
	if err != nil {
		return err
	}

	// orm.ErrNotFound also becomes 404, by content negotiation.
	task, err := orm.QueryOf[models.Task](tc.db).Find(c.Context(), id)
	if err != nil {
		return err
	}

	return c.Render("tasks/edit", task)
}
```

```go title="routes/web.go"
// One line registers index, store, edit, update and destroy
// routes, named tasks.index, tasks.store, and so on.
r.Resource("tasks", controllers.NewTaskController(db))
```

Você vai construir exatamente esse controller, passo a passo, em [Sua primeira app](/docs/first-app).

<Callout type="info">
Não se preocupe se `*web.Ctx`, `error` ou `[models.Task]` parecerem estranhos. A página [Pré-requisitos](/docs/prerequisites) explica cada conceito de Go que a documentação usa, com programas pequenos que você pode executar.
</Callout>

As páginas de **Primeiros passos** formam um caminho. Na primeira vez, leia na ordem:

1. [Pré-requisitos](/docs/prerequisites): as ferramentas para instalar e um guia de Go em 15 minutos.

5. [Configuração](/docs/configuration) e [Estrutura de diretórios](/docs/directory-structure): onde ficam as configurações e os arquivos.

Depois disso, a barra lateral funciona como referência: abra a página do recurso de que você precisa.
