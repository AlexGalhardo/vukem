---
title: Seu primeiro app
description: Construa uma lista de tarefas passo a passo, do vukem new até uma página CRUD funcionando, com validação, uma migration e testes.
---

Neste tutorial você constrói uma pequena **lista de tarefas**: uma página que lista as tarefas, um formulário que adiciona uma nova, uma página de edição que renomeia a tarefa ou a marca como feita, e um botão de excluir. No caminho você escreve uma migration, um model, uma request validada, um controller, duas views, as rotas e dois testes, e executa tudo isso.

Você vai aprender:

- como criar um projeto com `vukem new` e gerar arquivos com os comandos `make:*`
- como uma migration cria uma tabela no banco de dados, e como um model representa as linhas dela
- como um schema `z` valida a entrada do formulário e devolve os erros para o formulário
- como um resource controller e `r.Resource` transformam sete ações em rotas
- como testar o fluxo inteiro com `vukemtest`

O tutorial leva cerca de 30 minutos. Você precisa do Go 1.27.2 ou mais recente e da CLI `vukem` ([Instalação](/docs/installation)). O Node.js **não** é necessário. Se alguma sintaxe do Go parecer nova, deixe o [guia rápido de Go](/docs/prerequisites#go-em-15-minutos) aberto em outra aba.

## A ideia

Toda funcionalidade de um app web segue o mesmo caminho. Pense numa biblioteca: você pede um livro no balcão (a **requisição**), a bibliotecária consulta o catálogo (o **router**), vai até a estante certa (o **controller**), confere sua carteirinha (a **validação**), tira o livro da prateleira (o **banco de dados**) e entrega a você com uma capa bonita (a **view**).

Para a lista de tarefas, as peças são:

| Peça | Arquivo | Função |
| --- | --- | --- |
| <Term tip="Uma função Go que altera o schema do banco de dados, como criar uma tabela. Cada uma tem uma função Up e uma Down e roda uma única vez.">Migration</Term> | `database/migrations/…_create_tasks_table.go` | Cria a tabela `tasks` |
| <Term tip="Uma struct Go cujos campos correspondem às colunas de uma tabela. O ORM lê as linhas para dentro dela e grava de volta.">Model</Term> | `app/models/task.go` | Uma linha de `tasks` como struct Go |
| Request | `app/requests/task.go` | Os campos do formulário e suas regras |
| <Term tip="Uma struct cujos métodos (ações) respondem às requisições de um recurso: Index, Create, Store, Show, Edit, Update e Destroy.">Controller</Term> | `app/controllers/task_controller.go` | Lê a entrada, conversa com o banco, escolhe a resposta |
| Views | `resources/views/tasks/*.html` | As páginas HTML |
| Rotas | `routes/web.go` | Liga URLs às ações do controller |
| Teste | `tests/task_test.go` | Prova que tudo funciona |

E estas são as rotas que você terá no final:

| Método | URL | Ação | Nome da rota | O que faz |
| --- | --- | --- | --- | --- |
| `GET` | `/tasks` | `Index` | `tasks.index` | Lista as tarefas e mostra o formulário de nova tarefa |
| `POST` | `/tasks` | `Store` | `tasks.store` | Valida e salva uma nova tarefa |
| `GET` | `/tasks/{task}/edit` | `Edit` | `tasks.edit` | Mostra o formulário de edição |
| `PUT`, `PATCH` | `/tasks/{task}` | `Update` | `tasks.update` | Valida e salva as alterações |
| `DELETE` | `/tasks/{task}` | `Destroy` | `tasks.destroy` | Exclui a tarefa |

## Mãos à obra

<Steps>
<Step title="Crie o projeto">

```bash
vukem new todo --module example.com/todo
cd todo
vukem migrate
```

Aperte Enter na pergunta sobre a stack para ficar com HTMX. `vukem migrate` cria `storage/database.sqlite` e executa a migration de posts do starter:

```text
Migrated: 20260101000000_create_posts_table
```

O starter já contém um CRUD de posts. Você não mexe nele e constrói as tarefas ao lado, para poder comparar seu código com o `app/controllers/post_controller.go` do starter a qualquer momento.

</Step>
<Step title="Gere o model, a migration e o controller">

```bash
vukem make:model Task -m -c
```

```text
created app/models/task.go
created database/migrations/20261018003311_create_tasks_table.go
updated database/migrations/registry.go
created app/controllers/task_controller.go
```

- `-m` adiciona uma migration, `-c` um resource controller (e `-f` adicionaria uma [factory](/docs/database/factories-seeders)).
- O número no nome da migration é a data e hora atuais (`YYYYMMDDHHMMSS`), então o seu será diferente. Ele mantém as migrations na ordem em que você as escreveu.
- `registry.go` é a lista de todas as migrations. O gerador já adicionou a nova para você; não existe registro escondido.

</Step>
<Step title="Descreva a tabela">

Abra a migration gerada e adicione duas colunas entre `t.ID()` e `t.Timestamps()`:

```go title="database/migrations/20261018003311_create_tasks_table.go"
package migrations

import "github.com/AlexGalhardo/vukem/schema"

func m20261018003311CreateTasksTable() schema.Migration {
	return schema.Migration{
		ID: "20261018003311_create_tasks_table",
		Up: func(s *schema.Schema) error {
			return s.Create("tasks", func(t *schema.Table) {
				t.ID()
				t.String("title")
				t.Boolean("done").Default(false)
				t.Timestamps()
			})
		},
		Down: func(s *schema.Schema) error {
			return s.DropIfExists("tasks")
		},
	}
}
```

- `Up` roda quando você executa a migration, `Down` quando você a desfaz (rollback).
- `t.ID()` é uma chave primária `id` com auto-incremento. `t.Timestamps()` adiciona `created_at` e `updated_at`.
- `t.String("title")` é uma coluna de texto curto. `t.Boolean("done").Default(false)` é uma coluna verdadeiro/falso que começa como `false`.

Execute:

```bash
vukem migrate
```

```text
Migrated: 20261018003311_create_tasks_table
```

`vukem migrate:status` mostra cada migration e se ela já rodou. Veja [Migrations](/docs/database/migrations) para todos os tipos de coluna.

</Step>
<Step title="Preencha o model">

O model gerado só incorpora (embed) `orm.Model`. Adicione um campo por coluna:

```go title="app/models/task.go"
package models

import "github.com/AlexGalhardo/vukem/orm"

// Task is a row of the tasks table.
type Task struct {
	orm.Model

	Title string `json:"title"`
	Done  bool   `json:"done"`
}
```

`orm.Model` traz `ID`, `CreatedAt` e `UpdatedAt`. O ORM liga cada campo à coluna de mesmo nome em `snake_case` (`Title` → `title`), e a tabela é o plural do tipo (`Task` → `tasks`). As tags `json` dão nome aos campos quando a tarefa é enviada como JSON. Veja [ORM](/docs/database/orm).

</Step>
<Step title="Valide a entrada">

A entrada do usuário nunca deve chegar ao banco sem ser verificada. Gere uma request:

```bash
vukem make:request Task
```

```text
created app/requests/task.go
```

Substitua o conteúdo pelos campos do formulário e suas regras:

```go title="app/requests/task.go"
package requests

import "github.com/AlexGalhardo/vukem/z"

// Task is the input of the new-task and edit forms.
type Task struct {
	Title string `json:"title" form:"title"`
	Done  bool   `json:"done"  form:"done"`
}

// TaskSchema validates Task. An unchecked checkbox is not sent at
// all, so "done" defaults to false.
var TaskSchema = z.Struct[Task](z.Shape{
	"title": z.String().Trim().Min(3).Max(120),
	"done":  z.Bool().Default(false),
})
```

- `z.String().Trim().Min(3).Max(120)`: remove os espaços em volta do valor e depois exige de 3 a 120 caracteres.
- `z.Bool()` aceita `true`/`false`, `1`/`0`, `on`/`off` e `yes`/`no`. Um checkbox HTML marcado envia `on`; um desmarcado não envia nada.
- A tag `form` dá nome ao campo HTML, e a tag `json` ao campo JSON, então a mesma request serve para os dois.

Veja [Validação](/docs/basics/validation) para todas as regras.

</Step>
<Step title="Escreva o controller">

O controller gerado tem sete ações provisórias. Substitua o arquivo inteiro:

```go title="app/controllers/task_controller.go"
package controllers

import (
	"net/http"

	"github.com/AlexGalhardo/vukem/database"
	"github.com/AlexGalhardo/vukem/orm"
	"github.com/AlexGalhardo/vukem/web"

	"example.com/todo/app/models"
	"example.com/todo/app/requests"
)

// TaskController lists, creates, edits and deletes tasks.
type TaskController struct {
	db *database.DB
}

// NewTaskController returns a TaskController that uses db.
func NewTaskController(db *database.DB) *TaskController {
	return &TaskController{db: db}
}

// Index lists the tasks, newest first: GET /tasks.
func (tc *TaskController) Index(c *web.Ctx) error {
	tasks, err := orm.QueryOf[models.Task](tc.db).
		OrderBy("id", orm.Desc).
		Get(c.Context())
	if err != nil {
		return err
	}

	return c.Render("tasks/index", map[string]any{"Tasks": tasks})
}

// Store validates and saves a new task: POST /tasks.
func (tc *TaskController) Store(c *web.Ctx) error {
	in, err := web.Parse(c, requests.TaskSchema)
	if err != nil {
		return err
	}

	task := models.Task{Title: in.Title, Done: in.Done}
	if err := orm.Create(c.Context(), tc.db, &task); err != nil {
		return err
	}

	_ = c.Flash("success", "Task added.")

	return c.RedirectRoute("tasks.index")
}

// Edit shows the edit form: GET /tasks/{task}/edit.
func (tc *TaskController) Edit(c *web.Ctx) error {
	task, err := tc.find(c)
	if err != nil {
		return err
	}

	return c.Render("tasks/edit", task)
}

// Update validates and saves changes: PUT/PATCH /tasks/{task}.
func (tc *TaskController) Update(c *web.Ctx) error {
	task, err := tc.find(c)
	if err != nil {
		return err
	}

	in, err := web.Parse(c, requests.TaskSchema)
	if err != nil {
		return err
	}

	task.Title, task.Done = in.Title, in.Done
	if err := orm.Update(c.Context(), tc.db, &task); err != nil {
		return err
	}

	_ = c.Flash("success", "Task updated.")

	return c.RedirectRoute("tasks.index")
}

// Destroy deletes a task: DELETE /tasks/{task}.
func (tc *TaskController) Destroy(c *web.Ctx) error {
	task, err := tc.find(c)
	if err != nil {
		return err
	}

	if err := orm.Delete(c.Context(), tc.db, &task); err != nil {
		return err
	}

	// htmx swaps the row out with this empty body.
	if c.IsHTMX() {
		return c.String(http.StatusOK, "")
	}

	_ = c.Flash("success", "Task deleted.")

	return c.RedirectRoute("tasks.index")
}

// find loads the task in the URL, or fails with 404 Not Found.
func (tc *TaskController) find(c *web.Ctx) (models.Task, error) {
	id, err := c.ParamInt("task")
	if err != nil {
		return models.Task{}, err
	}

	return orm.QueryOf[models.Task](tc.db).Find(c.Context(), id)
}
```

O que cada parte faz:

- **`db *database.DB`** é a conexão com o banco. O controller a recebe em `NewTaskController` em vez de buscar uma variável global, o que facilita testá-lo.
- **`orm.QueryOf[models.Task](tc.db)`** inicia uma consulta tipada: `Get` retorna `[]models.Task`, `Find` retorna um `models.Task` ou `orm.ErrNotFound`.
- **`web.Parse`** lê o corpo do formulário (ou JSON) e aplica o schema. Com entrada inválida, ele retorna um erro de validação, e você o retorna sem alterar. Para um formulário do navegador, o Vukem então redireciona de volta ao formulário com as mensagens e a entrada antiga na sessão.
- **`c.Flash`** guarda uma mensagem de uso único para a próxima página. `c.RedirectRoute("tasks.index")` manda o navegador para a URL daquele nome de rota (`303 See Other` depois de um `POST`).
- **`c.ParamInt("task")`** lê `{task}` da URL. Um valor não numérico, como `/tasks/abc/edit`, vira 404, assim como um id que não existe.
- Não há ação `Create` nem `Show`: a página da lista já contém o formulário de nova tarefa, e uma tarefa não tem mais nada para mostrar. `r.Resource` registra apenas as ações que o controller tem.

</Step>
<Step title="Escreva as views">

As views são arquivos [`html/template`](https://pkg.go.dev/html/template) do Go. Cada página define um bloco `title` e um bloco `content`, e o layout `resources/views/layouts/app.html` os envolve. Crie a página da lista:

```html title="resources/views/tasks/index.html"
{{define "title"}}Tasks{{end}}
{{define "content"}}
<h1>Tasks</h1>

<form method="post" action="{{route "tasks.store"}}">
	{{csrfField}}
	<label>New task
		<input name="title" value="{{old "title"}}" required
			{{with error "title"}}aria-invalid="true"{{end}}>
	</label>
	{{with error "title"}}<p class="error">{{.}}</p>{{end}}
	<button type="submit">Add</button>
</form>

<ul class="list">
	{{range .Tasks}}
	<li>
		{{if .Done}}<s>{{.Title}}</s>{{else}}{{.Title}}{{end}}
		<a href="{{route "tasks.edit" "task" .ID}}">Edit</a>
		<button type="button" class="link danger"
			hx-delete="{{route "tasks.destroy" "task" .ID}}"
			hx-target="closest li" hx-swap="outerHTML"
			hx-confirm="Delete this task?">Delete</button>
	</li>
	{{else}}
	<li class="empty">Nothing to do.</li>
	{{end}}
</ul>
{{end}}
```

E a página de edição:

```html title="resources/views/tasks/edit.html"
{{define "title"}}Edit task{{end}}
{{define "content"}}
<h1>Edit task</h1>
<form method="post" action="{{route "tasks.update" "task" .ID}}">
	{{csrfField}}
	<input type="hidden" name="_method" value="PUT">
	<label>Title
		<input name="title" value="{{or (old "title") .Title}}" required>
	</label>
	{{with error "title"}}<p class="error">{{.}}</p>{{end}}
	<label>
		<input type="checkbox" name="done" {{if .Done}}checked{{end}}>
		Done
	</label>
	<button type="submit">Save</button>
</form>
{{end}}
```

Os helpers de view vêm do Vukem:

| Helper | O que faz |
| --- | --- |
| `route "tasks.edit" "task" .ID` | Monta a URL de uma rota nomeada: `/tasks/1/edit` |
| `csrfField` | Um input oculto `_token` para a proteção CSRF |
| `old "title"` | O valor que o usuário digitou antes de uma validação falhar |
| `error "title"` | A primeira mensagem de validação daquele campo, ou nada |

Formulários HTML só enviam `GET` e `POST`. O campo oculto `_method` diz ao middleware de method override do Vukem para tratar o `POST` como um `PUT`. O botão de excluir usa o `hx-delete` do htmx para enviar uma requisição `DELETE` de verdade e remover a linha no lugar.

Por fim, adicione um link à navegação em `resources/views/layouts/app.html`:

```html title="resources/views/layouts/app.html"
<nav>
	<a href="{{route "posts.index"}}">Posts</a>
	<a href="{{route "tasks.index"}}">Tasks</a>
	<a href="{{route "uploads.index"}}">Uploads</a>
</nav>
```

</Step>

```go title="tests/task_test.go"
package tests

import (
	"net/url"
	"testing"

	"github.com/AlexGalhardo/vukem/vukemtest"

	"example.com/todo/bootstrap"
)

func TestTasksCRUD(t *testing.T) {
	t.Parallel()

	app := vukemtest.New(t, bootstrap.New)
	c := app.Client(t)

	c.PostForm("/tasks", url.Values{"title": {"Buy milk"}}).
		AssertRedirect("/tasks").
		AssertSessionHas("success")

	vukemtest.AssertDatabaseHas(t, app, "tasks", map[string]any{
		"title": "Buy milk",
		"done":  false,
	})

	c.Get("/tasks").AssertOK().AssertSee("Buy milk")

	c.PostForm("/tasks/1", url.Values{
		"_method": {"PUT"},
		"title":   {"Buy oat milk"},
		"done":    {"on"},
	}).AssertRedirect("/tasks")

	vukemtest.AssertDatabaseHas(t, app, "tasks", map[string]any{
		"title": "Buy oat milk",
		"done":  true,
	})

	c.HTMX().Delete("/tasks/1").AssertOK()
	vukemtest.AssertDatabaseCount(t, app, "tasks", 0)
}

func TestTasksValidation(t *testing.T) {
	t.Parallel()

	app := vukemtest.New(t, bootstrap.New)

	app.Client(t).WithHeader("Referer", "/tasks").
		PostForm("/tasks", url.Values{"title": {"x"}}).
		AssertRedirect("/tasks").
		AssertSessionHasErrors("title")

	vukemtest.AssertDatabaseCount(t, app, "tasks", 0)
}
```

```bash
go test ./tests -run Tasks -v
```

```text
=== CONT  TestTasksValidation

--- PASS: TestTasksCRUD (0.03s)
PASS
```

`vukemtest.New` monta seu app com `bootstrap.New` no ambiente de teste: `APP_ENV=test`, um `APP_KEY` aleatório, um banco SQLite privado em memória e nenhuma porta de rede. Ele roda todas as migrations antes, então cada teste começa com as tabelas vazias, e `t.Parallel()` é seguro. `app.Client(t)` envia as requisições direto para o handler do app e guarda os cookies entre as chamadas, como um navegador. Veja [Testes](/docs/testing/overview).

## O que acontece por baixo dos panos

Acompanhe uma requisição, o `POST /tasks` inválido com `title=x`, do começo ao fim:

1. O servidor HTTP do Go aceita a conexão e executa a requisição em sua própria goroutine.
2. Os **middlewares de servidor** rodam: recuperam de panics, dão um id à requisição, registram no log, adicionam os cabeçalhos de segurança e transformam `_method=PUT` em `PUT` quando presente.
3. O **router** associa `POST /tasks` a `tasks.store`. Em seguida rodam os **middlewares de router**: o limite de corpo de 10 MiB, a sessão e a verificação de CSRF.
4. `TaskController.Store` chama `web.Parse`. O schema remove os espaços de `x`, vê que tem menos de 3 caracteres e retorna um `*errs.ValidationError` com a mensagem de `title`.
5. `Store` retorna esse erro. O handler central de erros vê um erro de validação num `POST` do navegador, então grava os erros e a entrada antiga na sessão (flash) e redireciona de volta à página de onde o formulário veio, com `303 See Other`.
6. O navegador segue o redirecionamento para `GET /tasks`. `Index` renderiza a página, e `old "title"` e `error "title"` leem os valores gravados, uma única vez.

Com `Accept: application/json` no passo 5, o mesmo erro vira uma resposta problem+json `422`, e com htmx vira um fragmento HTML. Você não escreveu nada desse código. Veja [Tratamento de erros](/docs/basics/error-handling) e o [ciclo de vida da requisição](/docs/architecture/lifecycle#request-lifecycle).

## Erros comuns

**Esquecer de rodar a migration.** Se você pular o `vukem migrate` depois de escrever a migration, `/tasks` responde `500`, e o log diz:

```text
orm: query tasks: SQL logic error: no such table: tasks (1)
```

Rode `vukem migrate`. Os testes não são afetados: `vukemtest.New` migra o próprio banco em memória.

**Um nome de rota errado numa view.** Os nomes de rota são verificados quando o template é executado. Um erro de digitação como `{{route "task.store"}}` gera um `500`, com este erro (uma linha só no log):

```text
template: tasks/index:5:30: executing "content" at <route "task.store">:
error calling route: router: no route named "task.store"
```

Rode `vukem route:list` e copie o nome exato.

**Um nome de parâmetro diferente do da rota.** `r.Resource("tasks", …)` dá ao parâmetro o nome do recurso no singular: `{task}`. `c.ParamInt("id")` não encontra nada ali, e toda edição, atualização e exclusão responde `404`.

```go
// Wrong: the route has {task}, not {id}.
id, err := c.ParamInt("id")

// Right
id, err := c.ParamInt("task")
```

**Salvar a struct da request diretamente.** `requests.Task` é o formato do formulário; `models.Task` é a linha da tabela. Copie os campos que você aceita (`Title`, `Done`) de uma para a outra, como `Store` e `Update` fazem, para que um cliente nunca consiga definir colunas que não deveria, como `id` ou `created_at`.
