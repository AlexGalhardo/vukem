---
title: Idempotency keys
description: Make retried POST and PATCH requests safe with the Idempotency-Key header.
---

```go
c, _ := app.Cache()
r.Group("/api/v1", func(g *router.Group) {
	g.Use(auth.Required(apiGuard)) // first, so the scope is the authenticated user
	g.Use(api.Idempotency(c.Store(), api.IdempotencyOptions{}))
})
```

The first `POST` or `PATCH` carrying an `Idempotency-Key` header runs and its response is stored; a retry with the same key gets the stored response with `Idempotent-Replayed: true` instead of running again.

| Situation | Answer |
| --- | --- |
| Same key, same request, finished | stored response, replayed |
| Same key while the first is still running | 409 |
| Same key, different method, URL or body | 422 (and an `idempotency.key_reused` security event) |
| Invalid key (1–255 printable characters) | 400 |
| Key sent but `Scope` is empty (no authenticated user, no `Authorization`, no custom `Scope`) | 400 (and an `idempotency.unscoped` security event) |
| Store unavailable | 503: the request is refused rather than risking a duplicate |

| Option | Default |
| --- | --- |
| `Methods` | `POST`, `PATCH` |
| `Required` | `false` (400 when the header is missing if `true`) |
| `TTL` | 24h for stored responses |
| `LockTTL` | 1 minute for in-flight requests |
| `MaxBody` | 1 MiB fingerprinted |
| `Scope` | the authenticated user (`auth.Principal`: guard and user id), else a SHA-256 of the `Authorization` header |

- Keys are **scoped to the caller**, so one user can never replay another's response.
- Put `Idempotency` **after** `auth.Required` (or `auth.Optional`): the scope is then the authenticated user, the same across token rotation, and a revoked token is refused before any replay. In front of auth only a hash of the `Authorization` header is available, and a revoked token could still replay its stored responses until they expire.
- Cookie sessions behind `auth.Required` are scoped by user too. For guests or a custom identity, **set `Scope`** to something that identifies the caller. Without it, a request carrying a key is refused with 400 instead of sharing one scope between every visitor:

```go
api.IdempotencyOptions{
	Scope: func(r *http.Request) string {
		return currentUserID(r) // "" for guests: their keyed requests get 400
	},
}
```

- To share keys between all callers on purpose (rare), return a constant such as `"public"`.
- Responses with status 500 or above are not stored, so the client can retry. `Set-Cookie` is never replayed.
- Any `cache.Store` works: memory, database or [Redis](/docs/database/redis).
