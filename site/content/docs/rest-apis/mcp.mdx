The [Model Context Protocol](https://modelcontextprotocol.io) (MCP) lets an AI agent discover and call the functions of an app. The `mcp` package serves revision `2026-07-28`, the stable one, from any Vukem app. It is not the `boost:mcp` command: Boost serves agents that **write** your app, `mcp` serves agents that **use** it.

You will learn how to:

- register typed tools whose schemas come from your Go structs
- add resources, prompts, completion and pagination
- ask the user to confirm an action with the `input_required` flow
- serve the server over stdio and over HTTP on the router
- protect the HTTP endpoint with any OAuth server
- test it with an in-memory client

## The idea

MCP speaks JSON-RPC 2.0. In this revision it is **stateless**: there is no `initialize` handshake and no session, so every request carries its protocol version and the client capabilities in `_meta`. A server behind a load balancer needs no sticky routing.

The package follows that model. It keeps no state between requests, and a tool is a plain Go function: `func(context.Context, P) (R, error)`, like a [`jsonrpc.Method`](/docs/rest-apis/json-rpc). The transport is its own, because MCP needs Server-Sent Events, no batches and per-request headers that `jsonrpc` does not have.

## Quick start

<Steps>

1. Register a tool. `P` is the input struct and `R` the result struct; both schemas are built once, from the `json`, `validate`, `enum` and `doc` tags, the same ones [OpenAPI](/docs/rest-apis/openapi) reads.

   ```go title="app/mcp/server.go"
   package appmcp

   import (
   	"context"

   	"github.com/AlexGalhardo/vukem/mcp"
   )

   type GetInvoice struct {
   	ID string `json:"id" validate:"required,uuid" doc:"invoice id"`
   }

   type Invoice struct {
   	ID    string `json:"id"`
   	Total int64  `json:"total" doc:"amount in cents"`
   }

   func New(invoices Invoices) *mcp.Server {
   	srv := mcp.NewServer(mcp.Config{Name: "billing", Version: "1.0.0"})

   	mcp.AddTool(srv, mcp.Tool{
   		Name:        "get_invoice",
   		Description: "Read one invoice.",
   		Annotations: &mcp.ToolAnnotations{ReadOnlyHint: new(true)},
   	}, func(ctx context.Context, in GetInvoice) (Invoice, error) {
   		return invoices.Find(ctx, in.ID)
   	})

   	return srv
   }
   ```

2. Serve it over HTTP on the router. The handler takes a `TokenVerifier` (see [Authorization](#authorization)); `InsecureNoAuth` is for localhost only.

   ```go title="routes/web.go"
   h, err := srv.HTTPHandler(mcp.HTTPConfig{
   	AllowedOrigins:       []string{"https://app.example.com"},
   	Resource:             "https://api.example.com/mcp",
   	AuthorizationServers: []string{"https://auth.example.com"},
   	Verifier:             verifier,
   })
   if err != nil {
   	return err
   }

   r.Handle("/mcp", h)
   r.Handle("GET "+h.MetadataPath(), h.MetadataHandler())
   ```

3. Or serve it over stdio from a command, for a local agent. Standard output carries only protocol messages: log to standard error or a file.

   ```go title="commands/mcp.go"
   return srv.ServeStdio(ctx, os.Stdin, os.Stdout)
   ```

</Steps>

## Tools

`AddTool` panics on a bad name, a duplicate or a non-struct `P`, like `http.ServeMux`: these are mistakes to catch at boot. A name has 1 to 128 characters of letters, digits, `_`, `-` and `.`.

When the model calls a tool the server parses the arguments with a strict `z` schema. Bad input becomes a tool result with `isError: true`, so the model can fix it and retry. The result `R` goes out as `structuredContent` with its JSON as a text fallback, and is checked against its own `validate` tags first.

What a tool function returns decides what the client sees:

| Return | The client gets |
| --- | --- |
| a value | `structuredContent` and the JSON text |
| `mcp.TextResult[T]{Text, Data}` | `Data` as `structuredContent` (with `outputSchema` and the `validate` check of `T`) and `Text` as the text the model reads; an empty `Text` falls back to the JSON |
| `mcp.Result` | exactly the content blocks you built |
| `mcp.ToolErrorf(...)` | a tool error shown to the model |
| a 4xx `*errs.HTTPError` | a tool error with its safe message |
| any other error or a panic | `-32603 Internal error`, nothing else; the cause is logged |

Use `mcp.Progress(ctx, 3, 10, "step")` to report progress; it sends nothing unless the client asked for it. Cancellation arrives as `ctx.Done()`: on HTTP a closed connection cancels the request, on stdio `notifications/cancelled` does. Always watch the context, because the server waits for your function.

## Confirm before acting

Return control to the user with `mcp.Confirm`. The server answers `input_required`, the client asks the user and retries the same call with the answer, and your function runs again from the start:

```go title="app/mcp/tools.go"
mcp.AddTool(srv, mcp.Tool{Name: "delete_invoice", Description: "Delete an invoice."},
	func(ctx context.Context, in GetInvoice) (Done, error) {
		ok, err := mcp.Confirm(ctx, "Delete invoice "+in.ID+"?")
		if err != nil {
			return Done{}, err // asks the user; also ErrElicitationUnsupported
		}

		if !ok {
			return Done{Deleted: false}, nil
		}

		return Done{Deleted: true}, invoices.Delete(ctx, in.ID)
	})
```

The `requestState` that travels through the client is signed with HMAC-SHA256 and bound to the caller, the method, the target, the arguments and a ten-minute expiry. An answer without a valid state is ignored and the user is asked again. Set `Config.StateKey` to the same secret on every instance. `mcp.Elicit` asks for a form instead of a yes or no.

## Resources, prompts and completion

```go title="app/mcp/catalog.go"
mcp.AddResource(srv, mcp.Resource{URI: "app://terms", Name: "terms", MIMEType: "text/markdown"},
	func(ctx context.Context) ([]mcp.ResourceContents, error) {
		return []mcp.ResourceContents{{Text: terms}}, nil
	})

mcp.AddResourceTemplate(srv, mcp.ResourceTemplate{URITemplate: "app://invoices/{id}", Name: "invoice"},
	func(ctx context.Context, uri string, vars map[string]string) ([]mcp.ResourceContents, error) {
		return readInvoice(ctx, vars["id"]) // return mcp.ErrNotFound for a missing one
	}, completeInvoiceIDs)

mcp.AddPrompt(srv, mcp.Prompt{Name: "summarize"}, func(ctx context.Context, a SummarizeArgs) (mcp.PromptResult, error) {
	return mcp.PromptResult{Messages: []mcp.PromptMessage{{Role: "user", Content: mcp.Text("Summarize " + a.ID)}}}, nil
}, nil)
```

Templates understand `{var}` (one segment) and `{+var}` (slashes allowed). A variable with a `..` segment or a NUL never matches, so a template over files cannot leave its root. Prompt arguments are strings on the wire, so the struct passed to `AddPrompt` has only string fields.

Lists are sorted and paged with an opaque cursor that is the last key of the page, so it survives inserts. `Config.PageSize` defaults to 50. List results carry `ttlMs` (from `Config.CacheTTL`, default 0) and `cacheScope: "private"`.

Call `srv.NotifyToolsChanged()`, `NotifyPromptsChanged()`, `NotifyResourcesChanged()` or `NotifyResourceUpdated(uri)` and every `subscriptions/listen` stream that opted in receives it.

## Authorization

The package does not depend on an OAuth implementation. It asks a `TokenVerifier`:

```go title="mcp/auth.go"
type TokenVerifier interface {
	VerifyAccessToken(ctx context.Context, token string, resource string) (*TokenInfo, error)
}
```

`TokenInfo` has `Subject`, `ClientID`, `Scopes`, `Resource`, `ExpiresAt` and `Extra`. Return `mcp.ErrInvalidToken` for a token that is unknown, expired or for another audience. Any other error is a 503 without detail: the check fails closed.

The handler does the rest:

- no token or a bad one is a 401 with `WWW-Authenticate: Bearer resource_metadata="..."`, plus `scope` and `error="invalid_token"`
- `TokenInfo.Resource` must equal `HTTPConfig.Resource`; an empty or different audience is refused
- a tool with `Scopes` is hidden from `tools/list` and refused with 403 `insufficient_scope` when the token lacks one
- a token in the query string (`?access_token=`) is a 400 and is never read
- `h.MetadataHandler()` serves the RFC 9728 protected resource metadata at `h.MetadataPath()`
- `mcp.TokenInfoFrom(ctx)` gives the verified token to your tools

## Protocol details

- `POST` only. `GET` and `DELETE` are 405; there is no session and `Mcp-Session-Id` is ignored.
- `MCP-Protocol-Version`, `Mcp-Method` and, for `tools/call`, `prompts/get` and `resources/read`, `Mcp-Name` are required and must match the body: a mismatch is a 400 with `-32020`. A name outside plain ASCII travels as `=?base64?...?=`.
- A version the server does not serve is a 400 with `-32022` and the list it supports.
- `Origin`, when present, must be in `AllowedOrigins`, otherwise 403. Non-browser clients send none.
- Progress and `subscriptions/listen` answer as Server-Sent Events with `X-Accel-Buffering: no`; everything else is plain JSON.
- Older clients (`2025-11-25`, `2025-06-18`, `2025-03-26`, `2024-11-05`) are answered per request with their own shape: `initialize` and `ping` work, no `resultType` is added, and no state is kept.

## Configuration

| Option | Default | Effect |
| --- | --- | --- |
| `Config.Name`, `Version` | required | identity in `server/discover` and every result |
| `Config.MaxMessageBytes` | 1 MiB | largest inbound message; more is a 413 (HTTP) or `-32600` (stdio) |
| `Config.PageSize` | 50 | items per list page |
| `Config.CacheTTL` | 0 | `ttlMs` of list results |
| `Config.StateKey` | random per process | HMAC key of `requestState` |
| `Config.StateTTL` | 10 minutes | lifetime of a `requestState` |
| `Config.MaxInFlight` | 32 | concurrent stdio requests; more is "Server busy" |
| `Config.MaxSubscriptions` | 1000 | open `subscriptions/listen` streams |
| `Config.KeepAlive` | 25 seconds | idle comment on event streams |
| `Config.ShutdownGrace` | 5 seconds | stdio drain time after end of input |
| `Config.Versions` | all five | revisions served |
| `HTTPConfig.InsecureNoAuth` | false | serve without authorization (localhost only) |

## Security

- Fail closed: `HTTPHandler` returns an error without a `Verifier` unless `InsecureNoAuth` is set.
- Clients never see a path, SQL, a panic message or an error chain: they get `Internal error`.
- Annotations are hints that clients treat as untrusted; enforce rules in the function.
- `Resource` must be the canonical URI of the endpoint, and the authorization server must issue tokens for it (RFC 8707).

## Testing

`mcptest` runs the server over pipes, adds the per-request metadata and answers `input_required` for you:

```go title="app/mcp/server_test.go"
func TestGetInvoice(t *testing.T) {
	c := mcptest.NewClient(t, New(fakeInvoices{}))

	res := c.CallTool("get_invoice", map[string]any{"id": id})
	if res.IsError {
		t.Fatal(res.Text())
	}
}
```

Use `mcptest.WithElicitation` to answer a confirmation, `c.Start` and `c.Wait` for concurrent calls and `c.Cancel` to cancel one.

## Common mistakes

Wrong: returning `fmt.Errorf("db: %w", err)` and expecting the model to read it. The client gets `Internal error`; return `mcp.ToolErrorf` for what the model can act on.

Wrong: a tool that ignores `ctx`. The server waits for it, so a cancelled request keeps a goroutine until it ends.

Wrong: the same URL for `Resource` and a different one in the access token audience. The 401 reads `error="invalid_token"` and nothing else.

## Not implemented

Logging, roots and sampling (deprecated in this revision), the tasks extension, `x-mcp-header` parameter mirroring and JSON-RPC batches. The `boost:mcp` command keeps its own small server.
