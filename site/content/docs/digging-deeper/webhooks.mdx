A webhook is an HTTP `POST` that one system sends to another when something happens: "email bounced", "payment succeeded", "order paid". It is how services talk to your app without you asking every minute. Vukem's `webhook` package covers both directions, with safety checks that are on by default.

| Direction | You are | Package pieces |
| --- | --- | --- |
| **Incoming** | the receiver (Resend, GitHub or Clerk call you) | `webhook.Standard`, `webhook.HMAC`, `webhook.Dedupe` |
| **Outgoing** | the provider (you call your users' URLs) | `webhook.Sender`, `webhook.NewSecret`, a [queue](/docs/digging-deeper/queue) |

You will learn:

- why every incoming webhook must be checked three ways: signature, time and event id;
- how to verify Standard Webhooks (Svix, Resend, Clerk) and plain HMAC signatures (GitHub, Shopify);
- how to run each event only once, even when the provider sends it twice;
- how to send signed webhooks from a queue, with retries, backoff and a delivery log;
- how Vukem stops a user from pointing a webhook at your internal network;
- how to test both directions.

## The idea

Anyone on the internet can `POST` to your webhook URL. Before your handler trusts a request, it must answer three questions, like a post office checking a registered letter:

1. **Is the seal real?** The sender signed the body with a secret only the two of you know. This is an <Term tip="Hash-based message authentication code: a fingerprint of the message computed with a secret key. Without the key, nobody can produce a matching fingerprint.">HMAC</Term>, computed with SHA-256 ([`crypto/hmac`](https://pkg.go.dev/crypto/hmac) in Go).
2. **Is the postmark recent?** A request someone captured last week must not work today. This is the <Term tip="The time window in which a signed request is accepted. Older or future-dated requests are refused, so a stolen request cannot be replayed later.">replay window</Term>.
3. **Have we opened this letter before?** Providers deliver **at least once**: when they do not hear back in time, they send the same event again. The event id lets you skip the copy.

Vukem answers each question with one middleware. A middleware in Vukem is a `func(http.Handler) http.Handler` that runs before your handler ([middleware basics](/docs/basics/middleware)):

```text
POST /webhooks/resend
   │
   ▼
webhook.Standard   → 413 if the body is too big
                   → 401 if the signature or time is wrong
   │
   ▼
webhook.Dedupe     → 200 + Webhook-Duplicate if already handled
                   → 409 if the same event is running now
   │
   ▼
your handler       → answer 2xx quickly
```

The signature check compares bytes with [`hmac.Equal`](https://pkg.go.dev/crypto/hmac#Equal), which takes the same time whether the first or the last byte differs. That stops an attacker from guessing the signature one byte at a time by measuring how fast you answer.

<Step title="Build the middleware and register the route">

```go title="routes/webhooks.go"
package routes

import (
	vukem "github.com/AlexGalhardo/vukem"
	"github.com/AlexGalhardo/vukem/router"
	"github.com/AlexGalhardo/vukem/webhook"

	"example.com/shop/app/controllers"
)

// Webhooks registers the routes providers call.
func Webhooks(r *router.Router, app *vukem.App) error {
	secret := app.Source.Get("RESEND_WEBHOOK_SECRET")

	// A missing or malformed secret stops the boot here.
	verify, err := webhook.Standard(secret, webhook.StandardOptions{})
	if err != nil {
		return err
	}

	c, err := app.Cache()
	if err != nil {
		return err
	}

	dedupe := webhook.Dedupe(
		c.Store(),
		webhook.StandardID,
		webhook.DedupeOptions{},
	)

	// Order matters: verify first, then dedupe.
	r.Post("/webhooks/resend", controllers.ResendWebhook).
		Use(verify, dedupe)

	return nil
}
```

</Step>

## Receiving webhooks

### Standard Webhooks

[Standard Webhooks](https://www.standardwebhooks.com) is a shared format used by Svix, Resend, Clerk and others. Each request carries three headers:

| Header | Example | Meaning |
| --- | --- | --- |
| `webhook-id` | `msg_2KWPBgLlAfxdpx2AI54pPJ85f4W` | the event id, the same on every retry |
| `webhook-timestamp` | `1792284303` | when it was sent, in Unix seconds |
| `webhook-signature` | `v1,jlZjAWp5sHA/Eq4V…` | `v1,` + the base64 HMAC-SHA256 of `<id>.<timestamp>.<body>` |

`webhook.Standard(secret, opts)` returns the middleware, or an error at boot. It then, for each request:

1. Reads at most `MaxBody` bytes (1 MiB). A bigger body answers 413.
2. Requires a non-empty `webhook-id` and a positive numeric timestamp.
3. Refuses a timestamp more than `Tolerance` (5 minutes) away from now, in the past **or** the future.
4. Computes the HMAC over `<id>.<timestamp>.<body>` and compares it with each `v1,` value in `webhook-signature`. The header may hold several, separated by spaces, which is how providers rotate secrets; one match is enough. Other versions (`v1a,…`) are skipped.
5. Puts the body back, so your handler can read it again with `c.BindJSON`.

Any failure answers 401 `Invalid webhook signature.` and logs a `webhook.signature_invalid` [security event](/docs/security/building-blocks#security-events) at WARN.

The secret is the provider's `whsec_<base64>` value. The `whsec_` prefix is optional, and the rest must be standard base64. Anything else is a boot error:

```text
webhook: Standard secret must be base64, optionally prefixed with whsec_
```

### Plain HMAC signatures

Older providers sign only the body and put the result in one header, such as GitHub's `X-Hub-Signature-256`. Use `webhook.HMAC(header, secret, maxBody)`:

```go title="routes/webhooks.go"
gh := []byte(app.Source.Get("GITHUB_WEBHOOK_SECRET"))

verifyGitHub, err := webhook.HMAC("X-Hub-Signature-256", gh, 1<<20)
if err != nil {
	return err
}

r.Post("/webhooks/github", controllers.GitHubWebhook).
	Use(verifyGitHub)
```

`maxBody` is in bytes; `0` or less means 1 MiB. The signature may be hex or base64 (standard or URL-safe), with or without a `sha256=` prefix, so most providers work as they are. An empty header name or secret fails the boot:

```text
webhook: HMAC needs a non-empty secret
```

`webhook.Middleware(header, secret, maxBody)` does the same checks but returns no error: with an empty secret it silently refuses every request with 401. Prefer `HMAC`, so a forgotten environment variable stops the deploy instead of breaking webhooks quietly.

<Callout type="warning" title="A body HMAC does not stop replays">
The signature covers only the body, so someone who captures one valid request can send it again later. Use `Standard` when the provider signs a timestamp, and add `Dedupe` in both cases.
</Callout>

Two building blocks help with custom schemes:

| Function | Returns |
| --- | --- |
| `webhook.VerifyHMAC(secret, payload, signature)` | `true` when `signature` is the HMAC-SHA256 of `payload`; constant-time; `false` for an empty secret or signature |
| `webhook.Sign(secret, payload)` | the hex HMAC-SHA256 of `payload`, for tests |

### Handle each event once

`webhook.Dedupe(store, id, opts)` remembers which event ids it has seen in a [cache store](/docs/digging-deeper/cache). `id` reads the event id from the request: `webhook.StandardID` reads `webhook-id`; for other providers write your own, for example `func(r *http.Request) string { return r.Header.Get("X-GitHub-Delivery") }`.

| Situation | Answer | Handler runs? |
| --- | --- | --- |
| First delivery | whatever your handler answers | yes |
| Same id, already answered with a status below 300 | `200` + `Webhook-Duplicate: true`, empty body | no |
| Same id while the first one is still running | `409 This webhook event is being processed.` | no (the provider retries) |
| Same id after your handler answered 300 or more | treated as a first delivery | yes |
| No id | `400 Missing webhook event id.` | no |
| Cache store down | `503 Webhook store unavailable.` | no (fail closed) |

Under the hood, `Dedupe` atomically adds a key built from the namespace and the event id with the value `running` for `LockTTL` (1 minute). After a status below 300 it stores `done` for `TTL` (72 hours, longer than providers' retry windows). After an error status it deletes the key, so the provider's retry runs your handler again. If the handler takes longer than `LockTTL`, a retry that arrives after the lock expired runs too, so keep handlers fast.

Keys are namespaced, so two providers that send the same id do not drop each other's events. The namespace is `DedupeOptions.Namespace`, or by default the matched route pattern (`POST /webhooks/github`). Put `Dedupe` on the route: outside one (a global middleware) the default is a single fixed namespace shared by every provider, never the request path, which the sender controls and could vary to replay an event. Set `Namespace` when one route serves several providers, or before renaming a webhook route, so ids handled under the old route stay remembered.

### Keep webhook routes out of sessions

Providers send no cookies, so loading a session for them is wasted work. Exclude the webhook routes from the session middleware:

```go title="routes/web.go"
err := vukem.DefaultMiddlewareWith(app, r, vukem.MiddlewareOptions{
	SessionBypass: []string{"/webhooks/"},
	CSRFBypass:    []string{"POST /webhooks/{provider}"},
})
```

The patterns use [`http.ServeMux` syntax](https://pkg.go.dev/net/http#hdr-Patterns-ServeMux): a trailing `/` covers the whole subtree. Vukem's CSRF check ([`http.CrossOriginProtection`](https://pkg.go.dev/net/http#CrossOriginProtection)) already lets through requests with neither an `Origin` nor a `Sec-Fetch-Site` header, which is what server-to-server calls look like. `CSRFBypass` makes the exemption explicit (it is logged at boot) and keeps the route working if a provider ever sends an `Origin` header. The signature protects the route instead.

For Stripe, use the ready-made handler from `contrib/stripe`; see [Billing](/docs/digging-deeper/billing).

## Sending webhooks

When your users (here, the shop's sellers) register a URL to hear about their orders, you become the provider. `webhook.Sender` does the hard parts:

- signs every attempt with the Standard Webhooks scheme, so receivers can verify with any Standard Webhooks library (or `webhook.Standard`);
- sends from a [queue](/docs/digging-deeper/queue) job, so a slow endpoint never slows a request, and retries with backoff;
- uses [`httpclient.Safe`](/docs/security/building-blocks#ssrf-safe-http-client), so a URL that resolves to loopback, a private network or the cloud metadata address is refused;
- keeps URLs, secrets and payloads out of the jobs table and the logs.

<Steps>
<Step title="Give each endpoint its own secret">

```go title="app/sellers/webhooks.go"
// "whsec_" followed by 32 random bytes in base64.
secret, err := webhook.NewSecret()
if err != nil {
	return err
}

_, err = db.ExecContext(ctx,
	`INSERT INTO seller_webhooks (seller_id, url, secret, active)
	 VALUES (?, ?, ?, ?)`,
	sellerID, url, secret, true,
)
```

Show the secret to the seller once, so they can verify your requests. Store it like a password: an [`orm.Encrypted[string]`](/docs/security/encryption) column is a good fit.

</Step>
<Step title="Create the sender and register its job">

```go title="app/sellers/sender.go"
package sellers

import (
	"context"
	"database/sql"
	"errors"

	"github.com/AlexGalhardo/vukem/database"
	"github.com/AlexGalhardo/vukem/webhook"
)

// NewSender looks up endpoints in seller_webhooks.
func NewSender(
	db *database.DB,
	log webhook.DeliveryLog,
) (*webhook.Sender, error) {
	return webhook.NewSender(webhook.SenderOptions{
		// Called on every attempt: the job stores only the id.
		Endpoint: func(
			ctx context.Context, id string,
		) (webhook.Endpoint, error) {
			var ep webhook.Endpoint
			var active bool
			err := db.QueryRowContext(ctx,
				`SELECT url, secret, active
				 FROM seller_webhooks WHERE seller_id = ?`,
				id,
			).Scan(&ep.URL, &ep.Secret, &active)
			if errors.Is(err, sql.ErrNoRows) ||
				(err == nil && !active) {
				// Dropped, not retried.
				return ep, webhook.ErrEndpointDisabled
			}
			return ep, err
		},
		Log: log,
		// The endpoint answered 410 Gone: stop sending to it.
		OnGone: func(ctx context.Context, id string) error {
			_, err := db.ExecContext(ctx,
				`UPDATE seller_webhooks SET active = ?
				 WHERE seller_id = ?`,
				false, id,
			)
			return err
		},
	})
}
```

`Endpoint` is required; without it `NewSender` returns `webhook: SenderOptions.Endpoint is required`. Because it runs on every attempt, a rotated secret or a changed URL applies to retries that are already waiting.

Register the job when the app builds its queue. `vukem.WithJobsFunc` gives you the app's database:

```go title="bootstrap/app.go"
vukem.WithJobsFunc(func(app *vukem.App) []queue.Registration {
	db, err := app.DB()
	if err != nil {
		panic(err) // becomes the error of app.Queue()
	}
	sender, err := sellers.NewSender(db, nil)
	if err != nil {
		panic(err)
	}
	return []queue.Registration{sender.Job()}
}),
```

`sender.Job()` registers the kind `webhook.DeliverKind` (`"webhook.deliver"`) with `Retries`, `Backoff` and a job timeout of `Timeout` + 5 seconds. Keep the same sender (or one built the same way) where you call `Send`.

</Step>
<Step title="Send an event">

```go title="app/orders/paid.go"
payload, err := json.Marshal(map[string]any{
	"type": "order.paid",
	"data": map[string]any{"order_id": order.ID},
})
if err != nil {
	return err
}

q, err := app.Queue()
if err != nil {
	return err
}

err = sender.Send(ctx, q, webhook.Delivery{
	// The same id on every retry, so the seller can dedupe.
	ID:       "order_paid_" + strconv.FormatInt(order.ID, 10),
	Endpoint: strconv.FormatInt(order.SellerID, 10),
	Payload:  payload,
})
```

`Send` only enqueues; a queue worker makes the HTTP call. Options such as `queue.OnQueue("webhooks")` may follow the delivery. `Send` refuses, before anything is queued:

| Problem | Error |
| --- | --- |
| empty endpoint id, or longer than 255 bytes | `webhook: delivery needs an endpoint id of at most 255 bytes` |
| payload that is not valid JSON | `webhook: delivery payload is not valid JSON` |
| id with spaces, dots or non-ASCII characters | `webhook: delivery id must be 1-255 printable ASCII bytes without dots or spaces` |

An empty `ID` becomes `msg_` + 32 random hex characters. Dots are refused because the signed content is `<id>.<timestamp>.<body>`: a dot in the id would make two different deliveries sign the same text.

</Step>

### What happens on each attempt

`sender.Deliver(ctx, d)` is the job handler. It makes one attempt, records it, and decides whether the queue should retry:

| Outcome | Recorded `Attempt.Error` | Retried? |
| --- | --- | --- |
| 2xx | empty | no, done |
| 410 Gone | `http_status` | no; `OnGone` runs (its error is logged, not retried) |
| 3xx | `http_status` | no; redirects are never followed, because the signed body would go elsewhere |
| any other status | `http_status` | yes |
| `Endpoint` returned `ErrEndpointDisabled` | `disabled` | no, dropped and logged at INFO |
| `Endpoint` returned another error | not recorded | yes |
| bad URL (not https, no host, has credentials) or bad secret | `invalid` | yes, so a fixed endpoint still gets the event |
| invalid delivery id | `invalid` | no |
| URL resolves to an internal address | `blocked_address` | yes |
| timeout or cancellation | `timeout` | yes |
| connection refused | `refused` | yes |
| TLS or certificate failure | `tls` | yes |
| any other network error (DNS, reset) | `network` | yes |

Each HTTP attempt is limited by `Timeout` (15 seconds). Up to 64 KiB of the answer is read and thrown away so the connection can be reused; the body never decides anything.

Retries follow `queue.Exponential(30 * time.Second)`: 30 s, 1 min, 2 min, 4 min… each delay capped at one hour, 8 retries, about two hours in total. After the last retry the job moves to the failed jobs, where `vukem queue:retry` can replay it.

### The delivery log

Sellers ask "why did my endpoint not get the event?". A <Term tip="Any value with a Record(ctx, webhook.Attempt) error method. The sender calls it after every attempt.">delivery log</Term> answers that. `webhook.Attempt` holds the endpoint id, event id, HTTP status (0 when no answer came), duration, error category and time; never the URL, secret or payload, so it is safe to show to the endpoint owner.

`webhook.SQLDeliveryLog` stores attempts in a table on SQLite, PostgreSQL or MySQL:

```go title="app/sellers/log.go"
// Table "webhook_deliveries" when the name is empty.
deliveries, err := webhook.NewSQLDeliveryLog(db, "")
if err != nil {
	return err
}

if err := deliveries.CreateTable(ctx); err != nil {
	return err
}

// The 20 newest attempts for seller 42, newest first.
attempts, err := deliveries.Recent(ctx, "42", 20)
```

| Column | Content |
| --- | --- |
| `id` | auto-increment key |
| `endpoint`, `event_id` | the ids (at most 255 bytes each, or `Record` refuses) |
| `status` | HTTP status, `0` without an answer |
| `duration_ms` | attempt duration in milliseconds |
| `error` | the category, cut at 1000 bytes |
| `attempted_at` | Unix milliseconds |

`CreateTable` also adds an index on `(endpoint, attempted_at)`. The table name must match `^[A-Za-z_][A-Za-z0-9_]{0,50}$`, so the index name fits the 63-byte limit of PostgreSQL and MySQL. `Recent` accepts a limit from 1 to 1000. The table grows forever, so prune old rows with a [scheduled](/docs/digging-deeper/scheduler) `DELETE`.

Already have a deliveries table? Wrap a function in `webhook.DeliveryLogFunc` and map the fields yourself:

```go title="app/sellers/log.go"
log := webhook.DeliveryLogFunc(
	func(ctx context.Context, a webhook.Attempt) error {
		_, err := db.ExecContext(ctx,
			`INSERT INTO seller_deliveries
			 (seller_id, message_id, http_status, ok)
			 VALUES (?, ?, ?, ?)`,
			a.Endpoint, a.EventID, a.Status, a.Error == "",
		)
		return err
	},
)
```

The sender calls `Record` from concurrent workers, with a context that outlives the job by up to 5 seconds (timed-out attempts are the ones worth keeping). A `Record` error is logged and never fails or retries the delivery, which already happened.

## Configuration

`webhook.StandardOptions`:

| Field | Type | Default | What it does |
| --- | --- | --- | --- |
| `MaxBody` | `int64` | 1 MiB | Largest body; bigger answers 413 |
| `Tolerance` | `time.Duration` | 5 minutes | Accepted distance between `webhook-timestamp` and now, both ways |
| `Now` | `func() time.Time` | `time.Now` | The clock, for tests |

`webhook.DedupeOptions`:

| Field | Type | Default | What it does |
| --- | --- | --- | --- |
| `TTL` | `time.Duration` | 72 hours | How long a handled id is remembered |
| `LockTTL` | `time.Duration` | 1 minute | How long a running delivery holds its id |
| `Namespace` | `string` | route pattern, else one fixed namespace | Keeps ids of different providers or handlers apart on a shared store |

`webhook.SenderOptions`:

| Field | Type | Default | What it does |
| --- | --- | --- | --- |
| `Endpoint` | `func(ctx, id) (Endpoint, error)` | required | Loads URL and secret on every attempt; `ErrEndpointDisabled` drops the delivery |
| `Log` | `DeliveryLog` | `nil` | Records every attempt |
| `OnGone` | `func(ctx, endpoint) error` | `nil` | Runs after a 410 Gone |
| `Logger` | `*slog.Logger` | `slog.Default()` | Delivery outcomes, without URLs, secrets or payloads |
| `Timeout` | `time.Duration` | 15 seconds | Limit per HTTP attempt |
| `Retries` | `int` | 8 | Retries after the first attempt; negative means none |
| `Backoff` | `func(attempt int) time.Duration` | exponential from 30 s, capped at 1 hour | Delay before retry n |
| `Now` | `func() time.Time` | `time.Now` | Clock for `webhook-timestamp` |
| `InsecureAllowHTTP` | `bool` | `false` | Allow `http://` endpoints; tests only |
| `InsecureAllow` | `[]netip.Prefix` | none | Internal ranges deliveries may reach (`127.0.0.0/8` for `httptest`); tests only |

Constants: `webhook.DeliverKind` is the job kind; `AttemptBlockedAddress`, `AttemptTimeout`, `AttemptRefused`, `AttemptTLS`, `AttemptNetwork`, `AttemptHTTPStatus`, `AttemptInvalid` and `AttemptDisabled` are the error categories.

## Security

What Vukem does by default:

- **Incoming**: the signature is checked before your code runs, in constant time; `Standard` refuses timestamps outside ±5 minutes; bodies are capped at 1 MiB; failures are logged as `webhook.signature_invalid`; `HMAC` and `Standard` fail the boot on an empty or malformed secret; `Dedupe` fails closed (503) when its store is down.
- **Outgoing**: every attempt is signed, and a missing or malformed secret fails the attempt instead of sending it unsigned; only `https` URLs without credentials; internal addresses are refused **at connect time**, after DNS, so a hostname that resolves to `169.254.169.254` is blocked too; redirects are not followed; jobs hold the endpoint id, never its URL or secret; logs and errors omit URL, secret and payload, and attempts store a category, never the resolved address or TLS detail.

What stays your job:

- Keep secrets in the environment or an encrypted column, never in code.
- Answer 2xx fast and do slow work in a queue job; providers retry on timeouts, which multiplies the work.
- Never enable `InsecureAllowHTTP` or `InsecureAllow` in production: endpoint URLs come from your users.

The full contract is in the [security overview](/docs/security/overview) and [security building blocks](/docs/security/building-blocks#webhook-signatures).

## Testing

### Incoming

Sign the request the way the provider would, with `webhook.SignStandard(secret, id, at, body)`, then send it with the [test client](/docs/testing/overview):

```go title="routes/webhooks_test.go"
package routes_test

import (
	"net/http"
	"strconv"
	"strings"
	"testing"
	"time"

	"example.com/shop/bootstrap"
	"github.com/AlexGalhardo/vukem/vukemtest"
	"github.com/AlexGalhardo/vukem/webhook"
)

const secret = "whsec_MfKQ9r8GKYqrTwjUPD8ILPZIo2LaLaSw"

func TestResendWebhookRunsOnce(t *testing.T) {
	app := vukemtest.New(t, bootstrap.New, vukemtest.Options{
		Env: map[string]string{"RESEND_WEBHOOK_SECRET": secret},
	})

	body := `{"type":"email.bounced"}`
	now := time.Now()

	sig, err := webhook.SignStandard(secret, "msg_1", now, []byte(body))
	if err != nil {
		t.Fatal(err)
	}

	post := func() *vukemtest.Response {
		return app.Client(t).
			WithHeader("webhook-id", "msg_1").
			WithHeader("webhook-timestamp",
				strconv.FormatInt(now.Unix(), 10)).
			WithHeader("webhook-signature", sig).
			Do(http.MethodPost, "/webhooks/resend",
				strings.NewReader(body), "application/json")
	}

	post().AssertNoContent()
	post().AssertOK().AssertHeader("Webhook-Duplicate", "true")

	// No signature at all.
	app.Client(t).
		Do(http.MethodPost, "/webhooks/resend",
			strings.NewReader(body), "application/json").
		AssertStatus(http.StatusUnauthorized)
}
```

For an HMAC route, set the header to `webhook.Sign(secret, body)`. To test the replay window without waiting, pass a fixed clock in `StandardOptions.Now`.

### Outgoing

Call `Deliver` directly against an [`httptest.Server`](https://pkg.go.dev/net/http/httptest#Server). It listens on plain HTTP at `127.0.0.1`, so opt in to both, in tests only:

```go title="app/sellers/sender_test.go"
func TestDeliverSigns(t *testing.T) {
	srv := httptest.NewServer(http.HandlerFunc(
		func(w http.ResponseWriter, r *http.Request) {
			if r.Header.Get("webhook-signature") == "" {
				t.Error("unsigned delivery")
			}
		},
	))
	defer srv.Close()

	sender, err := webhook.NewSender(webhook.SenderOptions{
		Endpoint: func(
			context.Context, string,
		) (webhook.Endpoint, error) {
			return webhook.Endpoint{URL: srv.URL, Secret: secret}, nil
		},
		InsecureAllowHTTP: true,
		InsecureAllow: []netip.Prefix{
			netip.MustParsePrefix("127.0.0.0/8"),
		},
	})
	if err != nil {
		t.Fatal(err)
	}

	err = sender.Deliver(t.Context(), webhook.Delivery{
		ID:       "msg_1",
		Endpoint: "42",
		Payload:  []byte(`{"type":"order.paid"}`),
	})
	if err != nil {
		t.Fatal(err)
	}
}
```

Without the two `Insecure` options the same test fails with `webhook: endpoint "42": needs an absolute https URL without credentials`, and with only `InsecureAllowHTTP` the attempt is recorded as `blocked_address`. That is the SSRF protection doing its job.

## Common mistakes

**Reading the body before the signature check.** The HMAC covers the raw bytes. A middleware that reads or rewrites the body first breaks every signature. Put `verify` first; it restores the body for whatever comes next.

**Dedupe before verify.**

```go
// Wrong: forged requests fill the cache with fake ids.
r.Post("/webhooks/resend", h).Use(dedupe, verify)

// Right
r.Post("/webhooks/resend", h).Use(verify, dedupe)
```

**A memory cache store with several instances.** Each instance remembers only its own events, so a retry that lands on another instance runs again. Use `CACHE_STORE=database` or [Redis](/docs/database/redis).

**Answering 4xx for events you do not handle.** The provider treats it as a failure and retries for days. Answer 2xx and ignore the event.

**Calling a user's URL inside a request.** One slow endpoint then slows your app, and nothing retries. Always go through `sender.Send`.

**A dot in the delivery id.** `ID: "order.paid.1001"` fails with `webhook: delivery id must be 1-255 printable ASCII bytes without dots or spaces`. Use `_` or `-`.
