Lumek is a web framework for **REST APIs and full-stack apps**: routing, validation, an ORM with migrations, authentication, JSON resources with problem+json errors, HTMX-first views and an optional Inertia + React frontend, all driven by one CLI.

<Callout type="warning">
Lumek is pre-1.0 and APIs will change between `v0.x` releases. Pages and callouts marked "Planned for ALPHA" or "Planned for BETA" describe the design target, not shipped code.
</Callout>

## Why Lumek

- **Standard library first.** Handlers and middleware are plain `net/http`. Any `http.Handler` works.
- **No magic.** No globals, no `init()` registration, no reflection-based dependency injection. Generators write code you own.
- **Typed end to end.** Typed configuration structs, named routes checked at boot, Zod-style schemas (`z`) that parse every input into Go types.
- **Batteries included, opt-in.** SQLite out of the box; PostgreSQL, Redis and MongoDB as separate driver modules, so you only download what you use.
- **APIs first-class.** RFC 9457 problem details, JSON-only route groups, CORS and body limits are built in.
- **Secure by default.** Security headers with CSP nonces, deny-by-default CORS, path-traversal-safe static files and fail-closed boot checks, mapped to the [OWASP Top 10:2025](/docs/security/overview).

## A taste

A handler is a function that receives a `*web.Ctx` and returns an `error`. Returned errors go to a central handler that renders the right response for the client.

```go title="routes.go"
func Routes(r *router.Router, posts *controllers.PostController) {
	r.Get("/", func(c *web.Ctx) error {
		return c.String(http.StatusOK, "Hello from Lumek")
	}).Name("home")

	r.Group("/admin", func(g *router.Group) {
		g.Resource("posts", posts) // posts.index, posts.store, posts.show…
	}).Name("admin.")
}

func (p *PostController) Show(c *web.Ctx) error {
	id, err := c.ParamInt("post") // non-numeric id → 404
	if err != nil {
		return err
	}

	post, ok := p.store.Find(id)
	if !ok {
		return errs.ErrNotFound // HTML page or problem+json, by content negotiation
	}

	return c.JSON(http.StatusOK, post)
}
```

## What works today

| Area | Status |
| --- | --- |
| Configuration: `.env` loading, typed `config.Load`, `config.Secret`, `APP_KEY` key derivation | Available |
| Application: providers, runners, commands, graceful shutdown, HTTP server with safe timeouts | Available |
| Router: groups, named routes, URL generation, resources, three middleware stacks, 404/405 | Available |
| `*web.Ctx`: input, responses, redirects, conditional requests, problem+json errors | Available |
| Middleware: recover, request id, logger, timeout, body limit, method override, CORS, static, secure headers with CSP nonces, gzip, JSON-only | Available |
| Validation with `z`, sessions with flash and old input, CSRF protection | Available |
| SQLite, generic ORM, schema builder and migrations | Available |
| `html/template` views with layouts and fragments, htmx 4 helpers | Available |
| `lumektest` fluent test client and database assertions | Available |
| `lumek` CLI: `new`, `serve`, `build`, `key:generate`, `make:*`, app commands | Available |
| Authentication, authorization, REST API starter, PostgreSQL, mail, cache, storage | Planned for ALPHA |
| OpenAPI, queues, Inertia + React, Vite, Redis, MongoDB | Planned for BETA |
