Vukem is a web framework for the [Go programming language](https://go.dev). It helps you build **APIs and full-stack web apps** without wiring every piece by hand: routing, validation, a database layer with migrations, authentication, views, background jobs, tests and a command-line tool that generates code for you.

You will learn:

- what a web framework does, and what Vukem adds on top of Go
- the ideas that shape Vukem (standard library first, no magic, typed end to end)
- what a Vukem handler looks like
- which features are available today
- where to go next, depending on what you know

## What a web framework does

When you open a page in your browser, the browser sends a **request** to a server ("give me `/tasks`"). The server runs some code and sends back a **response** (an HTML page, some JSON, an image). A web framework is the set of tools that makes writing that server code pleasant.

Think of a restaurant. The customer (the browser) orders from the menu. The waiter (the <Term tip="The part of a framework that looks at the URL and method of a request and decides which function answers it.">router</Term>) takes the order to the right cook. The cook (your <Term tip="A function that receives a request and writes a response. In Vukem it has the shape func(c *web.Ctx) error.">handler</Term>) prepares the dish. Security at the door (the <Term tip="Code that runs before and after handlers, for every request or for a group of routes: logging, sessions, security headers.">middleware</Term>) checks everyone who comes in.

Go already ships the basic kitchen in its standard library: the [`net/http`](https://pkg.go.dev/net/http) package can listen for requests and send responses. Vukem keeps that kitchen and adds the rest of the restaurant:

| You need to… | Go's standard library gives you | Vukem adds |
| --- | --- | --- |
| Map URLs to code | `http.ServeMux` patterns | Named routes, groups, resource controllers, URL generation |
| Read and check input | `r.FormValue`, `encoding/json` | `web.Parse` with Zod-style `z` schemas and field errors |
| Talk to a database | `database/sql` | Connections, a generic ORM, migrations, factories, seeders |
| Render pages | `html/template` | Layouts, partials, htmx fragments, Vite assets, Inertia |
| Keep users logged in | Cookies | Sessions, CSRF protection, guards, API tokens, 2FA |
| Run things later | Goroutines | Queues, a scheduler, events |
| Test it all | `net/http/httptest` | `vukemtest`: an in-process client with fluent assertions |

## Why Vukem

- **Standard library first.** Handlers and middleware are plain `net/http`. Any `http.Handler` works inside a Vukem app, and a Vukem app is an `http.Handler`.
- **No magic.** No global variables, no `init()` registration, no reflection-based dependency injection. Generators write ordinary Go files that you own and can read.
- **Typed end to end.** Configuration is loaded into typed structs. Named routes are checked when the app starts. Every input is parsed into Go types by a `z` schema before your code sees it.
- **Batteries included, opt-in.** SQLite works out of the box with a pure-Go driver (no C compiler). PostgreSQL, MySQL, Redis, MongoDB, S3 and WebSockets live in separate driver modules, so you only download what you use.
- **APIs first-class.** Errors become [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457) problem details, and JSON-only route groups, CORS and body limits are built in.
- **Secure by default.** Security headers with CSP nonces, deny-by-default CORS, path-traversal-safe static files and boot checks that fail closed, mapped to the [OWASP Top 10:2025](/docs/security/overview).

<Quote source="https://go.dev/doc/effective_go" author="Effective Go" title="go.dev/doc/effective_go">
A straightforward translation of a C++ or Java program into Go is unlikely to produce a satisfactory result.
</Quote>

Vukem follows that advice: it borrows the productivity of [Laravel](https://laravel.com) and [AdonisJS](https://adonisjs.com), but the code you write is idiomatic Go.

## A taste

A handler is a function that receives a `*web.Ctx` (the request and the response, together) and returns an `error`. When it returns an error, a central error handler turns it into the right response for whoever asked: an HTML page for a browser, a redirect with the form errors flashed to the session, or problem+json for an API client.

```go title="app/controllers/task_controller.go"
// Edit shows the edit form: GET /tasks/{task}/edit.
func (tc *TaskController) Edit(c *web.Ctx) error {
	// A non-numeric id such as /tasks/abc/edit becomes 404.
	id, err := c.ParamInt("task")
	if err != nil {
		return err
	}

	// orm.ErrNotFound also becomes 404, by content negotiation.
	task, err := orm.QueryOf[models.Task](tc.db).Find(c.Context(), id)
	if err != nil {
		return err
	}

	return c.Render("tasks/edit", task)
}
```

```go title="routes/web.go"
// One line registers index, store, edit, update and destroy
// routes, named tasks.index, tasks.store, and so on.
r.Resource("tasks", controllers.NewTaskController(db))
```

You will build this exact controller, step by step, in [Your first app](/docs/first-app).

Do not worry if `*web.Ctx`, `error` or `[models.Task]` look strange. The [Prerequisites](/docs/prerequisites) page explains every Go concept the docs use, with small programs you can run.
</Callout>

## How to read these docs

The **Getting started** pages are a path. Read them in order the first time:

1. [Prerequisites](/docs/prerequisites): the tools to install and a 15-minute Go primer.
2. [Installation](/docs/installation): install the `vukem` CLI and create a project.
3. [Starters](/docs/starters): pick HTMX, templ, Inertia or a JSON API.
4. [Your first app](/docs/first-app): build a to-do list with a form, validation, a migration and a test.
5. [Configuration](/docs/configuration) and [Directory structure](/docs/directory-structure): where settings and files live.

After that, the sidebar is a reference: open the page for the feature you need.
