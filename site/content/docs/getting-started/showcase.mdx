The best way to learn a framework after the tutorial is to read a real app that uses it. These four apps are built and maintained alongside Vukem. Each one is open source and deployed, so you can read the code that runs behind a live URL. They are also how Vukem is tested in the real world: their feedback drives most releases.

You will learn:

- which reference app to read for the kind of project you are building
- which Vukem features each app demonstrates, with links to their pages
- how to run one of them on your computer

## Pick one

Pick the app closest to what you are building and read it next to these docs. Start with the Quiz if you are new: it has no database and fits in an afternoon.

| App | Frontend | Data | Best for learning |
| --- | --- | --- | --- |
| [Quiz](#quiz-htmx) | HTMX 4, `html/template` | Embedded JSON | Server-rendered apps, i18n, a strict CSP |
| [Rifa](#rifa-inertia-and-vue) | Inertia v3 + Vue | PostgreSQL | Payments, a ledger, a public REST API, background work |
| [Marketplace](#marketplace-inertia-and-react) | Inertia v3 + React + Base UI | PostgreSQL, Redis, MongoDB | Multi-database apps, REST + GraphQL + gRPC, marketplace payments, tracing |
| [Tools](#tools-inertia-and-react) | Inertia v3 + React + Base UI | PostgreSQL | File conversion jobs, external engines as subprocesses, progress over SSE, a Telegram bot |

All four follow the layout described in [Directory structure](/docs/directory-structure): start reading at `bootstrap/app.go` to see everything the app wires, then `routes/` to see every URL, then the controllers they point to.

A Go quiz game with no database: the questions ship inside the binary as embedded JSON. Small enough to read in an afternoon.

What it demonstrates:

- **HTMX 4** with server-rendered `html/template` views and partial updates ([HTMX](/docs/frontend/htmx)).
- **Embedded content**: data and assets compiled into one binary ([Single binary](/docs/deployment/single-binary)).
- **Localization** with JSON catalogs and the `t` view function ([Localization](/docs/digging-deeper/localization)).
- **A strict, nonce-based CSP** with no `'unsafe-inline'` ([CSP and security headers](/docs/security/security-headers)).
- **Performance and accessibility**: a Lighthouse score of 100.

<Card title="Source code" href="https://github.com/AlexGalhardo/vukem-rifa-vuejs" icon="code">
AlexGalhardo/vukem-rifa-vuejs

A raffle platform ("rifa" in Portuguese) where users buy numbers and pay with PIX, Brazil's instant payment system.

What it demonstrates:

- **Inertia v3 with Vue** pages, forms and validation errors ([Inertia](/docs/frontend/inertia)).
- **PostgreSQL** with the ORM and migrations ([Database](/docs/database/overview)).
- **PIX payments through AbacatePay**, with verified, deduplicated [webhooks](/docs/digging-deeper/webhooks).
- **A ledger** that records every money movement of a raffle.
- **A public REST API** with typed handlers, OpenAPI and the **Scalar** reference ([OpenAPI](/docs/rest-apis/openapi)), protected by [API tokens](/docs/security/api-tokens).
- **Background work in one service**: the [scheduler](/docs/digging-deeper/scheduler) and the [queue](/docs/digging-deeper/queue) run inside `serve`.

## Marketplace (Inertia and React)

<Card title="Source code" href="https://github.com/AlexGalhardo/vukem-marketplace-reactjs" icon="code">

A small Mercado Livre-style marketplace: sellers list products, buyers pay, sellers get paid. The largest of the apps with a payments flow.

What it demonstrates:

- **Inertia v3 with React** and the **Base UI** component library ([Inertia](/docs/frontend/inertia)).
- **Three databases in one app**: PostgreSQL for the core data, [Redis](/docs/database/redis) for sessions, cache, queues and rate limits, [MongoDB](/docs/database/mongodb) for audit, telemetry and history documents.
- **Stripe Connect and PIX** payments, with payouts to sellers ([Stripe Connect](/docs/digging-deeper/billing#stripe-connect-marketplaces)).
- **Three API styles** over the same services: REST, [GraphQL](/docs/rest-apis/graphql) and [gRPC](/docs/rest-apis/grpc).
- **Tracing** with [OpenTelemetry](/docs/digging-deeper/opentelemetry).

## Tools (Inertia and React)

<CardGroup cols="2">
<Card title="Live app" href="https://tools.vukem.dev" icon="rocket">
tools.vukem.dev
</Card>
<Card title="Source code" href="https://github.com/AlexGalhardo/vukem-tools" icon="code">
AlexGalhardo/vukem-tools

</CardGroup>

A self-hosted file toolbox: convert, compress and optimise images, video, audio and documents, download videos, turn pixel art into SVG, and use developer tools such as a JSON formatter and a text diff. The whole backend is one Go binary.

What it demonstrates:

- **Inertia v3 with React** and the **Base UI** component library ([Inertia](/docs/frontend/inertia)).
- **Long conversions as queued jobs** on PostgreSQL, with progress pushed to the browser over [Server-Sent Events](/docs/digging-deeper/sse) ([Queues](/docs/digging-deeper/queue)).
- **External engines as subprocesses** (ffmpeg, libvips, Ghostscript and others), pinned by version; a tool whose engine is missing is not registered.
- **Streaming [uploads](/docs/digging-deeper/uploads)** for large files, behind accounts and per-user limits.
- **A Telegram bot** that talks to the same HTTP API.

<Callout type="info">
Several conversion engines are licensed under the GPL or the AGPL, so the project is not for commercial use. The `/licenses` page of the app lists each engine and its licence.
</Callout>

## Running one locally

Each repository's README lists its exact requirements. The usual flow:

<Steps>
<Step title="Clone it">

```bash
git clone https://github.com/AlexGalhardo/vukem-golang-quiz-htmx
cd vukem-golang-quiz-htmx
```

</Step>
<Step title="Create .env with a key">

```bash
vukem key:generate
```

When `.env` is missing, this copies `.env.example` to `.env` and writes a fresh `APP_KEY`. Fill in the other values the README asks for.

</Step>
<Step title="Start the databases (Rifa, Marketplace and Tools)">

```bash
docker compose up -d
vukem migrate
```

Rifa and Marketplace have a `compose.yaml` that starts their databases. The Quiz has no database, so skip this step. Tools needs PostgreSQL and its conversion engines installed; its README lists them.

</Step>
<Step title="Run it">

```bash
vukem serve
```

Open [http://localhost:3000](http://localhost:3000).

</Step>
</Steps>
