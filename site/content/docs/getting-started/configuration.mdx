Vukem has no stringly lookups such as `config("app.name")`. Configuration is read once at boot into typed structs; invalid values abort boot with **all** problems listed, not only the first one.

## `.env` files

The `config` package ships a small, standard-library-only `.env` parser. Values are resolved with this precedence, highest first:

1. The real process environment
2. `.env.<APP_ENV>.local`
3. `.env.local` (skipped when `APP_ENV=test`, so tests are reproducible)
4. `.env.<APP_ENV>`
5. `.env`

```dotenv title=".env"
APP_NAME=Blog
APP_ENV=development
# Written by vukem key:generate
APP_KEY=base64:your-32-byte-key-in-base64
APP_URL=http://localhost:3000

# ${VAR} interpolation
ASSET_URL=${APP_URL}/build

# Read the value from a file (Docker and Kubernetes secrets)
DB_PASSWORD=@file:/run/secrets/db

# Quotes and escapes
GREETING="Hello\nWorld"
export LOG_LEVEL=debug
```

Supported syntax: `KEY=value`, `export KEY=value`, single and double quotes, `\n` escapes inside double quotes (values may span lines), `#` comments, `${OTHER}` interpolation and the `@file:` prefix. The `@` keeps SQLite DSNs such as `file:storage/app.db` untouched.

Per-environment files override `.env`:

<CodeGroup>

```dotenv title=".env.example"
APP_NAME=Blog
APP_ENV=development
APP_KEY=
APP_URL=http://localhost:3000
```

```dotenv title=".env.test"
APP_DEBUG=true
LOG_LEVEL=warn
PORT=0
```

```dotenv title=".env.production"
APP_URL=https://blog.example.com
LOG_FORMAT=json
```

</CodeGroup>

<Callout type="tip">
Commit `.env.example` and git-ignore `.env` and `.env.*.local`. Never commit real secrets.
</Callout>

## Core settings

`vukem.New` loads the core `vukem.Config`:

| Variable | Default | Notes |
| --- | --- | --- |
| `APP_NAME` | `Vukem` | |
| `APP_ENV` | `development` | `development`, `production` or `test` |
| `APP_DEBUG` | `false` | Must be `false` when `APP_ENV=production` (boot error otherwise) |
| `APP_URL` | `http://localhost:3000` | Public origin of the app |
| `APP_KEY` | — | **Required in production** (and for any key-derived feature), at least 32 bytes, `base64:` prefix optional |
| `HOST` | `localhost` | Listen host; `0.0.0.0` for all IPv4 interfaces, `::` for IPv6 (dual-stack on most systems) |
| `PORT` | `3000` | Listen port, 0–65535 |
| `SHUTDOWN_TIMEOUT` | `15s` | Graceful shutdown budget |
| `HTTP_MAX_HEADER_BYTES` | `65536` | Cap on the request line plus headers (64 KiB; 4096–1048576); larger requests get 431 |
| `TRUSTED_PROXIES` | empty (trust nobody) | Comma-separated CIDRs or IPs whose `X-Forwarded-For` sets `c.IP()`; an invalid entry is a boot error ([Deploy](/docs/deployment/docker-and-railway#trusted-proxies)) |
| `CLIENT_IP_HEADER` | empty | Read the client IP from this single-IP header (e.g. `X-Real-IP`) instead of `X-Forwarded-For`, only from `TRUSTED_PROXIES` peers |
| `RATE_LIMIT_IPV6_PREFIX` | `64` | Prefix length `ratelimit.ByIP` groups IPv6 clients by (1–128); IPv4 stays per address |
| `TRUST_FORWARDED_PROTO` | `false` | Treat `X-Forwarded-Proto: https` from a trusted proxy as HTTPS (HSTS); requires `TRUSTED_PROXIES` |
| `HSTS_FORCE` | `false` | Send HSTS on every response in production when the TLS proxy's range cannot be trusted ([trade-offs](/docs/deployment/docker-and-railway#hsts-without-a-trusted-range)); validated in every environment (requires an `https://` `APP_URL`), applied only in production (a boot warning otherwise) |
| `LOG_LEVEL` | `info` | `debug`, `info`, `warn`, `error` |
| `LOG_FORMAT` | `text` (`json` in production) | `text` or `json` |
| `LOG_DEDUP_WINDOW` | `1m` in production, off elsewhere | Repeated identical errors become one `repeated` summary per window; `0` disables it |

## Typed module config

Fill your own structs with `config.Load[T]` using `env` and `default` tags. Fields of nested structs without an `env` tag are filled recursively.

```go title="config/mail.go"
type Mail struct {
	Host     string        `env:"MAIL_HOST"     default:"localhost"`
	Port     int           `env:"MAIL_PORT"     default:"1025"`
	From     string        `env:"MAIL_FROM"`
	Password config.Secret `env:"MAIL_PASSWORD"`
	Timeout  time.Duration `env:"MAIL_TIMEOUT"  default:"10s"`
	Cc       []string      `env:"MAIL_CC"` // comma-separated
}

func LoadMail(app *vukem.App) (Mail, error) {
	return config.Load[Mail](app.Source) // every conversion error, joined
}
```

Supported field types: `string`, `bool`, ints, uints, floats, `time.Duration`, `[]string` (comma-separated), `*url.URL`, `config.Secret` and any `encoding.TextUnmarshaler`.

### Testing with a fake environment

Tests inject configuration instead of calling `os.Setenv`:

```go
src := config.MapSource(map[string]string{
	"APP_KEY": config.GenerateKey(),
	"APP_ENV": "test",
})

app, err := vukem.New(vukem.WithSource(src))
```

`vukem.WithEnv(fsys, getenv)` loads `.env` files from any `fs.FS` (for example `fstest.MapFS`) with a custom `getenv`.

## `Secret`

`config.Secret` holds sensitive values. Every formatting path prints `[redacted]`: `fmt` (`%v`, `%s`, `%#v`), `encoding/json`, `encoding.TextMarshaler` and `log/slog`.

```go
cfg.Password.Reveal() // the real value, only where it is used
fmt.Println(cfg.Password)        // [redacted]
app.Log.Info("mail", "cfg", cfg) // password logged as [redacted]
```

## `APP_KEY`

- Required. `vukem key:generate` writes one to `.env` (creating it from `.env.example` when missing); `--show` prints a key instead and `--force` replaces an existing one, which makes current sessions and encrypted data unreadable. Where only the compiled app exists (Docker, CI), `./app key:generate` prints a new key without booting the app or writing any file; see [CLI](/docs/cli/overview#app_key-without-the-global-cli). In code, `config.GenerateKey()` returns 32 random bytes from `crypto/rand`, `base64:`-encoded.
- Required in production and whenever `APP_ENV` is unset or empty. Only with an explicit `APP_ENV=development` or `test` does an app boot without it (development logs one warning), and every key-derived feature fails closed on use: cookie sessions (`SESSION_DRIVER=cookie`, the default, so `DefaultMiddleware` is still a boot error), `app.Crypt` (nil; `Decrypt` and `SetCookie` return `crypt.ErrNoKey`, `Encrypt` panics), `app.Key.Derive` (panics), `app.DeriveKey` (returns `config.ErrKeyMissing`), encrypted ORM columns (`orm.ErrNoEncrypter`) and the maintenance bypass cookie (disabled). An API-only app with token auth and no encryption runs without a key. A malformed key is always a boot error.
- The decoded key is available as `app.Key`. Never use it directly: derive a purpose-specific key with HKDF-SHA256 so cookies, sessions and encryption never share key material.

```go
sessionKey := app.Key.Derive("session", 32) // HKDF info "vukem:session"

signer, err := app.DeriveKey("signed.urls", 32) // config.ErrKeyMissing instead of a panic
```

`APP_PREVIOUS_KEYS` lists former keys (comma-separated, same `base64:` format). They only open or verify what they sealed or signed (encrypted cookies and columns, queued mail, cookie sessions, the maintenance bypass, and signed URLs and social state through `app.DerivePreviousKeys`); everything new uses `APP_KEY`. `vukem key:rotate` moves the current key there and writes a new one; see [Encryption](/docs/security/encryption#key-rotation).

## Secure defaults

| Check | Behaviour |
| --- | --- |
| Missing `APP_KEY` in production or with `APP_ENV` unset, malformed `APP_KEY` anywhere | Boot error |
| Missing `APP_KEY` with explicit `APP_ENV=development`/`test` | Boots; key-derived features fail closed on use |
| `APP_DEBUG=true` with `APP_ENV=production` | Boot error |
| `PORT` out of range | Boot error |
| Invalid `TRUSTED_PROXIES` entry; `TRUST_FORWARDED_PROTO` or `CLIENT_IP_HEADER` without `TRUSTED_PROXIES`; an invalid or list `CLIENT_IP_HEADER`; `HSTS_FORCE` without an `https://` `APP_URL`; `RATE_LIMIT_IPV6_PREFIX` outside 1–128; `HTTP_MAX_HEADER_BYTES` outside 4096–1048576 | Boot error |
| Debug error details | Only when `Services.Debug` is set; never in production |
