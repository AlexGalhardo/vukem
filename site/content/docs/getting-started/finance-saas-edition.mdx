`vukem new money --example finance --edition saas` creates the multi-tenant SaaS edition of [vukem-finances](https://github.com/AlexGalhardo/vukem-finances): workspaces with roles, public sign-up, Free and Pro plans, and a billing layer you operate.

**There is currently no hosted service.** The edition is for whoever runs it: you deploy it on your own VPS, you configure the payment and mail providers, and you serve your own customers. The MIT license allows commercial use, so you can charge for the service you run.

Which page is for me? This page is for operating the multi-tenant edition for customers. If you want the offline-first app for yourself or your family, read [Finance app, personal edition](/docs/finance-personal-app) instead.

You will learn:

- what the SaaS edition contains
- how to create the project and run it locally
- how to put it on a VPS with Caddy and automatic HTTPS
- what you must configure as the operator: Stripe, AbacatePay, mail and backups

## What it is

The SaaS edition is the same application and binary as the other edition, chosen by `APP_EDITION=saas`. It is a project you read and change: every file is yours the moment `vukem new` writes it.

| Feature | What it does |
| --- | --- |
| Workspaces and roles | One workspace per customer group; owner, admin, member and read-only viewer, enforced on the server; invitations and ownership transfer |
| Sign-up | Public `/register` with email verification |
| Billing | A card subscription with Stripe, or a one-off PIX payment with AbacatePay; only the workspace owner manages it |
| Plan limits | Free: 1 account, 100 transactions a month, 1 member. Pro: unlimited, plus CSV import, budgets and alerts |
| Public API | A JSON API with scoped tokens, described by an OpenAPI file served at `/api/v1/openapi.json` |
| Remote MCP | AI clients connect to a customer's workspace at `/mcp` with OAuth; it needs an `https` `APP_URL` |
| Telegram bot | Customers link a chat and record expenses with short messages; it stays off until you set `TELEGRAM_BOT_TOKEN` |
| Admin panel | Users, workspaces, subscriptions and a revenue page for the emails in `ADMIN_EMAILS` |

Access to the Pro plan changes only from a verified webhook, never from the page a checkout returns to. Every table has a `workspace_id` and every query goes through the scoped helper, so one workspace never reads another's rows. The generated tests check it.

This page covers operating the edition. The full documentation is in the [application repository](https://github.com/AlexGalhardo/vukem-finances/tree/main/docs).

## Create the project

You need Go 1.27.4 or newer, Bun, Docker and the `vukem` CLI ([Installation](/docs/installation)).

```bash
vukem new money --example finance --edition saas
cd money
```

`--edition saas` writes `APP_EDITION=saas` into `.env`. The project is the exported application: its own `Dockerfile`, `compose.yaml`, `compose.prod.yaml` and `deploy/` guide are in the folder. The CLI refuses `--pm` other than `bun` and `--assets-image`, because the application ships its own `bun.lock` and `Dockerfile`.

To run it locally on SQLite with a mail catcher:

```bash
docker compose up -d --build --wait
```

Open `http://localhost:3000`. Mail goes to the catcher at `http://localhost:8025`. Without Docker, run `bun install`, `vukem migrate` and `vukem serve`.

## Run it on a VPS

The production stack runs the app behind Caddy with automatic HTTPS. The database is one SQLite file on a volume, so run one replica.

1. Get a server with Docker and the Compose plugin, and a domain name you control.
2. Point an `A` record (and `AAAA` if the server has IPv6) of the domain at the server, and wait until it resolves. Caddy asks Let's Encrypt for a certificate on the first request.
3. Allow only SSH, 80 and 443 in the firewall. Docker edits firewall rules itself, so publish nothing beyond what `compose.prod.yaml` already does.
4. Copy `.env.example` to `.env` and set `APP_KEY`, `APP_EDITION=saas`, the mail and payment settings below. Keep the file readable only by you.
5. Start it:

```bash
export APP_DOMAIN=finance.example.com
docker compose -f compose.prod.yaml up -d --build --wait
```

`compose.prod.yaml` derives `APP_URL` as `https://` plus `APP_DOMAIN`, and forces `APP_ENV=production`. The step-by-step guide, with the firewall and the update procedure, is `deploy/README.md` in the project.

### The prebuilt image

You do not have to build the image. The application publishes `ghcr.io/alexgalhardo/vukem-finances` (also on Docker Hub as `alexgalhardo/vukem-finances`). `vukem new money --prebuilt --example finance --edition saas` writes a folder with only `compose.yaml`, `.env` and `README.md` that runs that image on SQLite, with the version the CLI embeds. It is a quick way to try the edition, not a production stack: use `compose.prod.yaml` for a server.

## What you configure as the operator

| Area | Settings | Notes |
| --- | --- | --- |
| Stripe | `STRIPE_KEY` (a restricted key), `STRIPE_PRICE_PRO`, `STRIPE_WEBHOOK_SECRET` | Create a recurring price for Pro and point a webhook at `/stripe/webhook`. The first subscription of a workspace gets a 14-day trial |
| AbacatePay | `ABACATEPAY_API_KEY`, `ABACATEPAY_WEBHOOK_SECRET`, `PIX_PRICE_PRO_MONTHLY_CENTS`, `PIX_MONTHS_OPTIONS` | One-off PIX payments for 1, 3 or 12 months, with no automatic renewal; the webhook is `/abacatepay/webhook` |
| Mail | `MAIL_MAILER=resend`, `MAIL_FROM`, `RESEND_API_KEY`, the Resend webhook secret | Sign-up needs email verification, so without a working mail setup nobody can register. Add a Resend webhook for `email.bounced` and `email.complained` at `/webhooks/resend` |
| Admin | `ADMIN_EMAILS` | The addresses allowed into `/admin` |
| Backups | the `db:backup` command | Take a consistent snapshot before every update and on a schedule; copy it off the server |

Amounts are integer cents and come from the server, never from the browser. Production refuses `AUTH_REQUIRE_EMAIL_VERIFICATION=false`.

### Backups

`db:backup` writes a consistent snapshot of the SQLite file while the app runs:

```bash
docker compose -f compose.prod.yaml exec app /app/app db:backup \
  -to /app/storage/backups/$(date +%F).sqlite
```

Copy the file off the server. Never copy `database.sqlite` itself while the app runs. To go back, restore a snapshot and start the older version: migrations do not run backwards.
