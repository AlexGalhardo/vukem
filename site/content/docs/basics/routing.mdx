description: Map URLs and HTTP methods to handlers with named routes, groups, resource routes and URL generation, on top of Go's http.ServeMux.
---

Every request that reaches your app carries a method (`GET`, `POST`…) and a path (`/posts/42`). Routing is how you tell Vukem which function answers each pair. This page builds the routes of a small blog with posts and comments, one step at a time.

You will learn how to:

- register routes for each HTTP method and read values from the URL;
- name routes and build URLs from those names instead of typing paths;
- share a prefix, a name and middleware across routes with groups;
- generate the seven RESTful routes of a controller with one line;
- understand what happens when no route matches, and how to catch mistakes at boot.

## The idea

Think of the router as the front desk of a hotel. A guest says "room 42, please" and the desk sends them to the right door. The router reads "`GET /posts/42`" and sends the request to the right <Term tip="A function that receives the request and writes the response. In Vukem its type is web.HandlerFunc: func(c *web.Ctx) error.">handler</Term>.

| Request | Route pattern | Handler |
| --- | --- | --- |
| `GET /` | `/` | `controllers.Home` |
| `GET /posts` | `/posts` | `posts.Index` |
| `GET /posts/42` | `/posts/{post}` | `posts.Show` |
| `POST /posts/42/comments` | `/posts/{post}/comments` | `comments.Store` |

Vukem does not reinvent matching. Under the hood it uses [`http.ServeMux`](https://pkg.go.dev/net/http#ServeMux) from Go's standard library, which learned methods and wildcards in Go 1.22 (the Go blog explains it in [Routing enhancements](https://go.dev/blog/routing-enhancements)). Vukem adds what ServeMux lacks: route names, groups, resource routes, nicer 404 and 405 pages, and checks that run before your server starts.

A handler is a plain Go function. In Go, [functions are values](https://go.dev/tour/moretypes/24): you can pass them to other functions, which is exactly what `r.Get("/", handler)` does.

## Where routes live

Routes are plain Go code, registered when the app is built:

```go title="routes/registry.go"
package routes

import (
	"github.com/AlexGalhardo/vukem"
	"github.com/AlexGalhardo/vukem/router"
)

// All lists the route files, in order.
func All() []func(r *router.Router, app *vukem.App) error {
	return []func(r *router.Router, app *vukem.App) error{
		Web,
	}
}
```

`bootstrap/app.go` passes each function to `vukem.WithRoutes`. `vukem.New` calls them in order, after every provider's `Register`, so a route file may use the services providers added. If a route file returns an error, `vukem.New` stops and returns it. Routes that need a client opened in a provider's `Boot` go in `vukem.WithRoutesAfterBoot` instead; see [the application lifecycle](/docs/architecture/lifecycle).

You may also use the `router` package on its own, without an app:

```go title="main.go"
package main

import (
	"log"
	"net/http"

	"github.com/AlexGalhardo/vukem/router"
	"github.com/AlexGalhardo/vukem/web"
)

func main() {
	// nil services: logging falls back to slog.Default().
	r := router.New(nil)

	r.Get("/", func(c *web.Ctx) error {
		return c.String(http.StatusOK, "Welcome to the blog")
	})

	h, err := r.Handler()
	if err != nil {
		log.Fatal(err)
	}

	log.Fatal(http.ListenAndServe(":3000", h))
}
```

`router.New(services)` takes the shared [`*web.Services`](/docs/basics/http-context#services) every handler can reach. When you pass `nil`, it creates an empty one. When `services.URLs` is empty, the router installs itself there, so `c.URL(...)` works in handlers.

## Defining routes

There is one method per HTTP verb. Each returns a `*router.Route` you can name or give middleware.

| Method | Registers | Notes |
| --- | --- | --- |
| `r.Get(path, h)` | `GET` | Also answers `HEAD` (ServeMux does this for every `GET` pattern) |
| `r.Post(path, h)` | `POST` | |
| `r.Put(path, h)` | `PUT` | |
| `r.Patch(path, h)` | `PATCH` | |
| `r.Delete(path, h)` | `DELETE` | |
| `r.Options(path, h)` | `OPTIONS` | |
| `r.Match(methods, path, h)` | one route per method | Methods are upper-cased (`"get"` works); returns `[]*router.Route` |
| `r.Any(path, h)` | every method | `vukem route:list` shows its method as `ANY` |

```go title="routes/web.go"
posts := controllers.NewPostController(db)

r.Get("/posts", posts.Index).Name("posts.index")
r.Post("/posts", posts.Store).Name("posts.store")
r.Get("/posts/{post}", posts.Show).Name("posts.show")
r.Put("/posts/{post}", posts.Update).Name("posts.update")
r.Delete("/posts/{post}", posts.Destroy).Name("posts.destroy")

// One handler for two methods, e.g. a search form that may GET or POST.
r.Match([]string{"GET", "POST"}, "/search", posts.Index)
```

`posts.Index` is a [method value](https://go.dev/ref/spec#Method_values): a method bound to the `posts` value, usable anywhere a function is expected. [Controllers](/docs/basics/controllers) explains the pattern.

### The root route

`r.Get("/", h)` matches **only** the home page. In ServeMux syntax a bare `/` would match every path (it is a prefix), so Vukem registers it as `/{$}`, where `{$}` means "the path ends here". That is why `route:list` prints `/{$}`.

Inside a group the same rule applies: `/` means the group's own page, never a catch-all.

| You write | Pattern registered | Matches |
| --- | --- | --- |
| `r.Get("/", h)` | `GET /{$}` | only `/` |
| `r.Get("", h)` | `GET /{$}` | only `/` |
| `g.Get("/", h)` in group `/admin` | `GET /admin/{$}` | only `/admin/`; `/admin` redirects there (307) |
| `g.Get("", h)` in group `/admin` | `GET /admin` | only `/admin` |

Pick one per group: `g.Get("/", h)` makes `/admin/` the canonical URL, `g.Get("", h)` makes it `/admin`. Before v0.28, `g.Get("/", h)` was a ServeMux prefix pattern that also answered `/admin/anything`.

## Route parameters

A segment in braces is a wildcard. Its value is available in the handler:

| Pattern | Matches | Does not match | Read with |
| --- | --- | --- | --- |
| `/posts/{post}` | `/posts/42`, `/posts/hello` | `/posts`, `/posts/42/edit` | `c.Param("post")` |
| `/files/{path...}` | `/files/a`, `/files/2026/q3.pdf` | | `c.Param("path")` → `2026/q3.pdf` |
| `/posts/{$}` | `/posts/` only | `/posts/42` | |

```go title="app/controllers/post_controller.go"
func (pc *PostController) Show(c *web.Ctx) error {
	// "42" in /posts/42 becomes the int64 42. A value that is not
	// a number, such as /posts/abc, returns errs.ErrNotFound (404).
	id, err := c.ParamInt("post")
	if err != nil {
		return err
	}

	post, err := orm.QueryOf[models.Post](pc.db).Find(c.Context(), id)
	if err != nil {
		return err
	}

	return c.JSON(http.StatusOK, post)
}
```

Rules that come from ServeMux:

- A wildcard fills a **whole segment**. `/posts/{id}.json` is not a valid pattern; use `/posts/{id}` and a query parameter, or a separate route.
- `{name...}` must be the last segment. It captures the rest of the path, slashes included.
- Values are already URL-decoded: `/posts/hello%20world` gives `hello world`.
- When two patterns could match, the **more specific** one wins. `/posts/create` beats `/posts/{post}`, so the order you register them in does not matter. Two patterns that are equally specific are a [build error](#compiling-and-checking-routes).

`c.Param` returns `""` for a name the pattern does not have. To validate several parameters with a schema, use `web.ParseParams` (see [Requests](/docs/basics/requests#typed-input)).

## Named routes and URL generation

Typing `"/posts/" + id` everywhere breaks the day you rename the path. Give the route a name instead and ask the router for its URL:

```go title="routes/web.go"
r.Get("/posts/{post}", posts.Show).Name("posts.show")
```

```go
u, err := r.URL("posts.show", "post", 42)
// u == "/posts/42", err == nil
```

Parameters come as name/value pairs: `"post", 42`. Values are formatted with `fmt.Sprint` and path-escaped (`"a b"` becomes `a%20b`). A `{path...}` value keeps its slashes and escapes each segment.

`URL` returns an error instead of a wrong link:

| Call | Error |
| --- | --- |
| `r.URL("nope")` | `router: no route named "nope"` |
| `r.URL("posts.show")` | `router: URL("posts.show") missing param "post"` |
| `r.URL("posts.show", "post", 1, "x", 2)` | `router: URL("posts.show") unknown param "x"` |
| `r.URL("posts.show", "post")` | `router: URL("posts.show") needs name/value pairs` |

In handlers and templates you rarely call `r.URL` yourself:

| Helper | Use it for |
| --- | --- |
| `c.URL(name, params...)` | Same as `r.URL`, returns `(string, error)` |
| `c.MustURL(name, params...)` | Returns the URL, or `"#"` and logs the error. Handy where the route is known to exist |
| `c.RedirectRoute(name, params...)` | Redirects to the route (see [Responses](/docs/basics/responses#redirects)) |
| `{{ route "posts.show" "post" .ID }}` | The same in [views](/docs/basics/views) |

Calling `r.URL` compiles the router (see [below](#compiling-and-checking-routes)), so routes added after the first call are ignored.

`rt.FullName()` returns a route's name with its group prefixes, and `rt.Path()` returns its full pattern path.

## Groups

Groups share three things among their routes: a path prefix, a name prefix and middleware. The blog keeps its back office under `/admin`:

```go title="routes/web.go" nocompile
r.Group("/admin", func(g *router.Group) {
	g.Use(appmw.RequireAdmin(app.Source.Get("ADMIN_TOKEN")))

	// GET /admin/stats, named "admin.stats".
	g.Get("/stats", admin.Stats).Name("stats")

	g.Group("/reports", func(rg *router.Group) {
		// GET /admin/reports/{year}, named "admin.reports.show".
		rg.Get("/{year}", admin.Report).Name("show")
	}).Name("reports.")
}).Name("admin.")
```

What happens under the hood:

- **Prefixes add up.** A group's prefix is cleaned: a missing leading `/` is added and a trailing `/` removed, so `"admin"`, `"/admin"` and `"/admin/"` are the same.
- **Name prefixes add up too**, and they are applied when the router compiles. That is why `.Name("admin.")` may come after the function: the inner routes still get it. Include the dot yourself.
- **Group middleware covers every route of the group**, including routes registered before the `g.Use` call and routes of nested groups. Outer groups run first. The full order is on the [Middleware](/docs/basics/middleware#the-order-of-execution) page.
- `fn` may be `nil`: `r.Group("/admin", nil)` returns an empty group you fill later with `g.Get(...)`.

A group has the same route methods as the router: `Get`, `Post`, `Put`, `Patch`, `Delete`, `Options`, `Match`, `Any`, `Handle`, `Group`, `Resource` and `APIResource`. A group can also wrap the error handler for its routes with `.ErrorHandler(...)`, for example to give an API group its own error shape ([one error handler per group](/docs/basics/error-handling#one-error-handler-per-group)).

### Middleware on one route

`Use` on a route adds middleware to that route only. It runs after the router and group middleware:

```go title="routes/web.go"
// Covers may be large: allow 20 MiB on this route only.
r.Post("/posts/{post}/cover", posts.UploadCover).
	Name("posts.cover").
	Use(middleware.BodyLimit(20 << 20))
```

### Host routes

Some apps answer on two hostnames from one process: the site on `example.com` and a public API on `api.example.com/v1`. `r.Host` creates a group whose routes match only requests for that host:

```go title="routes/api.go"
r.Host("api.example.com", func(g *router.Group) {
	g.Use(apiCORS)
	g.Group("/v1", func(v1 *router.Group) {
		v1.Name("api.")
		v1.Get("/games", games.Index).Name("games")
	})
})
```

Under the hood the route is registered as the [`ServeMux`](https://pkg.go.dev/net/http#ServeMux) pattern `GET api.example.com/v1/games`, so the standard library does the matching:

- The request's `Host` header decides, with any port ignored (`api.example.com:8443` matches). Other hosts never reach these routes; they get the main routes or a `404`.
- A host route is more specific than the same path without a host, so `example.com/v1/games` and `api.example.com/v1/games` can both exist.
- Middleware given to the group with `Use` runs for that host only, which is where per-host CORS or headers go.
- `r.URL("api.games")` returns the scheme-relative `//api.example.com/v1/games`, so a link or redirect built on the main site still reaches the API host. Routes without a host keep returning a path.
- `route:list` prints the host before the path, and `RouteInfo.Host` carries it for tools.
- The host must be a lowercase name without port, path or wildcard. `r.Host("API.example.com", ...)` fails when the routes compile: `router: GET /x: invalid host "API.example.com" (lowercase name, no port, path or wildcard)`.

#### A host that serves only its own routes

By default a host group only adds routes: a request for `api.example.com/login` that matches none of them falls through to the main routes. Call `Only()` on the host group to make it the only thing the host serves:

```go title="routes/api.go"
r.Host("api.example.com", func(g *router.Group) {
	g.Get("/", home.APIIndex)
	g.Group("/v1", apiV1)
}).Name("host.").Only()
```

- Any other path on that host gets a `404` (or a `405` with `Allow` when another method matches) from the error handler, never a main route.
- Those answers skip the router middleware added with `r.Use` (the web stack: sessions, CSRF), so they set no session cookie.
- The host group's `ErrorHandler` still runs for them, which is how an API host answers every miss as problem+json.
- `Only` on a group without a host fails when the routes compile.

The framework's own routes, such as the `/up` health check, are main routes, so an `Only()` host no longer reaches them. Register the ones the host must keep inside the group. `app.HealthHandler()` is the handler of `/up` (`200 {"status":"ok"}`, `Cache-Control: no-store`, `?checks=1` runs the health checks):

```go title="routes/api.go"
r.Host("api.example.com", func(g *router.Group) {
	g.Get("/up", app.HealthHandler())
	g.Group("/v1", apiV1)
}).Name("host.").Only()
```

#### One set of routes under two prefixes

To serve the same handlers at `/api/v1` on the main host and at `/v1` on the API host, register them from one function twice. Give each copy its own name prefix, as route names must be unique:

```go title="routes/api.go"
func apiV1(g *router.Group) {
	g.Get("/games", games.Index).Name("games")
}

func API(r *router.Router) {
	r.Group("/api/v1", apiV1).Name("api.")
	r.Host("api.example.com", func(g *router.Group) {
		g.Group("/v1", apiV1).Name("public.")
	}).Only()
}
```

`r.URL("api.games")` returns `/api/v1/games` and `r.URL("public.games")` returns `//api.example.com/v1/games`.

Behind a proxy, the `Host` header must be the public name the client used. Most platforms forward it unchanged; check yours if host routes answer `404` in production only.

## Resource routes

Most blog pages follow the same shape: list posts, show one, a form to create one, save it, and so on. `Resource` registers all of these routes from one controller:

```go title="routes/web.go"
r.Resource("posts", posts)
```

The router checks which methods the controller has, through small Go [interfaces](https://go.dev/tour/methods/9), and registers only those:

| Controller method | Interface | Route | Name |
| --- | --- | --- | --- |
| `Index` | `router.Indexer` | `GET /posts` | `posts.index` |
| `Create` | `router.Creator` | `GET /posts/create` | `posts.create` |
| `Store` | `router.Storer` | `POST /posts` | `posts.store` |
| `Show` | `router.Shower` | `GET /posts/{post}` | `posts.show` |
| `Edit` | `router.Editor` | `GET /posts/{post}/edit` | `posts.edit` |
| `Update` | `router.Updater` | `PUT /posts/{post}` and `PATCH /posts/{post}` | `posts.update` (the `PATCH` route has no name) |
| `Destroy` | `router.Destroyer` | `DELETE /posts/{post}` | `posts.destroy` |

Each method must have the handler signature `func(c *web.Ctx) error`. A method with another signature is not routed, and no error tells you so.

### The parameter name

The member parameter is the singular of the last segment, with a few English rules:

| Segment | Parameter |
| --- | --- |
| `posts` | `{post}` |
| `categories` | `{category}` |
| `boxes`, `classes`, `dishes`, `matches` | `{box}`, `{class}`, `{dish}`, `{match}` |
| `news` | `{new}` (ends in `s`; pick another name or register routes by hand) |
| `staff` | `{staff}` (unchanged) |

Read it with `c.Param("post")` or `c.ParamInt("post")`.

### APIs, subsets and middleware

```go title="routes/web.go"
// JSON API: no Create and Edit form routes, even if the controller
// has those methods.
r.APIResource("posts", posts)

// Keep only some actions...
r.Resource("posts", posts).Only("index", "show")

// ...or drop some.
r.Resource("posts", posts).Except("destroy")

// Middleware for every remaining action of this resource.
r.Resource("posts", posts).Except("destroy").Use(requireLogin)
```

`Only` and `Except` take action names (`"index"`, `"create"`, `"store"`, `"show"`, `"edit"`, `"update"`, `"destroy"`) and remove the other routes from the router. Call them **before** `Use`, so the middleware lands only on the routes that stay.

Because removed routes are really gone, you may register the same resource twice with different middleware. Readers browse freely; writers must sign in:

```go title="routes/web.go"
r.Resource("posts", posts).Only("index", "show").Use(optionalLogin)
r.Resource("posts", posts).Except("index", "show").Use(requireLogin)
```

### Nested resources

Comments belong to a post. A dot in the name nests the resource:

```go title="routes/web.go"
comments := controllers.NewCommentController(db)

r.Resource("posts.comments", comments).
	Only("index", "store", "show", "destroy")
```

| Route | Name |
| --- | --- |
| `GET /posts/{post}/comments` | `posts.comments.index` |
| `POST /posts/{post}/comments` | `posts.comments.store` |
| `GET /posts/{post}/comments/{comment}` | `posts.comments.show` |
| `DELETE /posts/{post}/comments/{comment}` | `posts.comments.destroy` |

A comment id is unique on its own, so `/posts/1/comments/7` repeats information. `Shallow()` moves the member routes (`show`, `edit`, `update`, `destroy`) to the top level and keeps the names:

```go title="routes/web.go"
r.Resource("posts.comments", comments).
	Only("index", "store", "show", "destroy").
	Shallow()
```

| Route | Name |
| --- | --- |
| `GET /posts/{post}/comments` | `posts.comments.index` |
| `POST /posts/{post}/comments` | `posts.comments.store` |
| `GET /comments/{comment}` | `posts.comments.show` |
| `DELETE /comments/{comment}` | `posts.comments.destroy` |

`Shallow()` does nothing on a resource that is not nested. Inside a group, the group prefix stays: in group `/api`, shallow routes are `/api/comments/{comment}`.

## Mounting plain handlers

Some libraries hand you a standard [`http.Handler`](https://pkg.go.dev/net/http#Handler), such as a metrics endpoint or another router. `Handle` mounts it as is:

```go title="routes/web.go"
// A method prefix limits the route to GET (and HEAD).
r.Handle("GET /metrics", metricsHandler)

// No method: every method. A trailing slash mounts a whole subtree.
r.Handle("/legacy/", http.StripPrefix("/legacy", legacyMux))
```

The pattern uses raw ServeMux syntax: unlike `r.Get`, a trailing `/` keeps its prefix meaning here. Group prefixes and middleware still apply.

Two adapters convert between the worlds:

| Function | Converts |
| --- | --- |
| `router.Adapt(h, services)` | A `web.HandlerFunc` into an `http.Handler` with its own `*web.Ctx` (errors go to the error handler; `c.RouteName()` is empty) |
| `router.Wrap(h)` | An `http.Handler` into a `web.HandlerFunc` that always returns `nil` |

## When nothing matches

ServeMux answers unknown paths with plain text. Vukem sends them through the [error handler](/docs/basics/error-handling) instead, so they look like the rest of your app:

| Situation | Status | Extra |
| --- | --- | --- |
| No route has this path | `404 Not Found` | |
| The path exists, but not for this method | `405 Method Not Allowed` | `Allow` header listing the methods the path accepts |

Browsers get an HTML page (your `errors/404` view when it exists). JSON clients get [problem details](https://www.rfc-editor.org/rfc/rfc9457):

```bash
curl -i -X DELETE http://localhost:3000/posts -H "Accept: application/json"
```

```text
HTTP/1.1 405 Method Not Allowed
Allow: GET, HEAD, POST
Content-Type: application/problem+json

{"type":"about:blank","title":"Method Not Allowed","status":405,
"instance":"/posts"}
```

The router finds the allowed methods by trying `GET`, `HEAD`, `POST`, `PUT`, `PATCH`, `DELETE` and `OPTIONS` against the path. Server middleware (static files, CORS) runs before this step, so a file in `public/` is served even though no route matches it.

## Compiling and checking routes

Registering a route only records it. The router turns the records into a real ServeMux once, the first time one of these runs:

- `r.Handler()` (the app calls it when the server starts);
- `r.URL(...)`;
- the first request through `r.ServeHTTP`.

At that moment it wraps each handler in its middleware and checks the whole table. These mistakes are reported as errors:

| Mistake | Error text |
| --- | --- |
| Two routes with the same full name | `router: duplicate route name "x" (GET /a and GET /b)` |
| Two patterns that match the same requests | `router: GET /posts/{slug}: pattern "GET /posts/{slug}" ... conflicts with pattern "GET /posts/{id}" ... (conflicts with GET /posts/{id} [posts.show])` |
| A broken pattern | `router: GET /posts/{id: parsing "GET /posts/{id": at offset 11: bad wildcard segment (must end with '}')` |

`vukem serve` and `vukemtest.New` call `Handler()` at boot, so these errors stop the app before it accepts traffic. `r.ServeHTTP` panics on them instead, because it cannot return an error; call `r.Handler()` yourself when you use the router directly.

Compiling happens once. Routes added afterwards are **ignored** (they answer 404). `r.Compiled()` reports whether compiling already happened.

`rt.Doc(v)` attaches documentation to a route, such as an `api.Operation`. The [OpenAPI generator](/docs/rest-apis/openapi) reads it back.

### Listing routes

`r.Routes()` returns one `router.RouteInfo` per route, in registration order:

| Field | Content |
| --- | --- |
| `Method` | `GET`, `POST`…, or `ANY` for `Any` and method-less `Handle` |
| `Path` | The full pattern, group prefixes included |
| `Name` | The full name, or `""` |
| `Middleware` | Function names of the router, group and route middleware (server middleware is not listed) |
| `Doc` | The value given to `Doc` |

The `vukem route:list` command prints the same table; `vukem route:list --json` prints it as JSON for scripts.

## Security

- **Patterns are exact.** A route answers only the method and path you wrote. `GET` routes also answer `HEAD`, which never has a body.
- **Ids that are not numbers name nothing.** `c.ParamInt` turns `/posts/abc` into a 404, not a 500 or a database error.
- **Generated URLs are escaped.** `r.URL` path-escapes every value, so a title with `/` or `?` cannot change the target route.
- Routing is not authorization. Protect routes with middleware (see [Authentication](/docs/security/authentication#protecting-routes-with-middleware)) and check ownership in the handler (see [Authorization](/docs/security/authorization)).

## Testing

`vukemtest` boots the whole app and sends requests in memory. Test that routes exist, answer the right status and use the right names:

```go title="tests/routes_test.go"
package tests

import (
	"testing"

	"github.com/AlexGalhardo/vukem/vukemtest"

	"blog/bootstrap"
)

func TestRoutes(t *testing.T) {
	t.Parallel()

	app := vukemtest.New(t, bootstrap.New)
	c := app.Client(t)

	c.Get("/").AssertOK()
	c.Get("/posts/abc").AssertNotFound()

	c.Delete("/posts").
		AssertStatus(405).
		AssertHeader("Allow", "GET, HEAD, POST")

	u, err := app.Router.URL("posts.comments.show", "comment", 7)
	if err != nil || u != "/comments/7" {
		t.Fatalf("URL = %q, %v", u, err)
	}
}
```

Replace `blog` with your module name from `go.mod`. `AssertRedirectRoute(name, params...)` checks that a response redirects to a named route. See [Testing](/docs/testing/overview).

## Common mistakes

**The same name twice.** Boot fails with `router: duplicate route name "posts.show" (GET /posts/{post} and GET /articles/{post})`. Give each route its own name.

**Two wildcards in the same place.** `/posts/{id}` and `/posts/{slug}` match the same requests, so boot fails with `... matches the same requests as GET /posts/{id}`. Keep one pattern and decide inside the handler, or use different paths (`/posts/by-slug/{slug}`).

**Adding routes after the server started.** They are silently ignored and answer 404. Register every route in a route file, before `Handler()` runs.

**HTML forms that send `PUT` or `DELETE`.** Browsers only send `GET` and `POST`. Add a hidden `_method` field and install `middleware.MethodOverride()` as server middleware (the default stack does). See [Middleware](/docs/basics/middleware#built-in-middleware).
