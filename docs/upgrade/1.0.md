# Upgrading to v1.0

**Estimated effort:** low for apps on the last `v0` release, medium from earlier ones. v1.0 freezes the API: after this upgrade, later `v1` releases follow the [stability policy](../stability.md).

## Before you start

- Go **1.27.4** or later (the minimum in every `go.mod`; it carries the `net/http`, `go` command and compiler security fixes).
- On your current version, run `go fix ./...` before you upgrade: on `v0.25` or earlier it rewrites uses of the deprecated aliases that later releases removed (see [Renamed or removed APIs](#renamed-or-removed-apis-public-api-review)).
- Upgrade the CLI and every Vukem module to the same version:

```sh
go install github.com/AlexGalhardo/vukem/cmd/vukem@v1.0.0
go get github.com/AlexGalhardo/vukem@v1.0.0
go get github.com/AlexGalhardo/vukem/drivers/postgres@v1.0.0 # and each driver or contrib module you use
go mod tidy
```

## Required changes

### vukem upgrade now updates the CLI; use vukem update for the project (from v0.43)

The project upgrade (framework requirement moved to the CLI's version, starter notes under `.vukem/upgrade/`, `--check`) is now `vukem update`. It also moves the `drivers/*` and `contrib/*` modules and every other direct Go dependency to the newest stable tag, and every `package.json` dependency to the newest stable version written exactly, then runs the package manager's `install` and `go build ./...`. Pass `--dry-run` to list the changes first, `--go-only` or `--js-only` to limit them.

Until `vukem upgrade` becomes the CLI self-update, it only prints a pointer to `vukem update`. Change scripts and CI that ran `vukem upgrade` or `vukem upgrade --check` to `vukem update` and `vukem update --check`; note that `--check` now also exits 1 when a dependency is behind and needs network access.

### Multipart forms with method override (from v0.19)

`middleware.MethodOverride` no longer parses multipart bodies to find `_method`, so uploads can stream. Put the override in the form's action URL:

```html
<!-- before -->
<form method="post" enctype="multipart/form-data" action="/posts/1">
  <input type="hidden" name="_method" value="PUT">
<!-- after -->
<form method="post" enctype="multipart/form-data" action="/posts/1?_method=PUT">
```

URL-encoded forms keep working with the hidden field.

### gRPC reflection in production (from v0.20)

`GRPC_REFLECTION_IN_PRODUCTION` is now `GRPC_INSECURE_REFLECTION_IN_PRODUCTION`, and the constant `grpc.ReflectionInProductionEnv` is `grpc.InsecureReflectionInProductionEnv`.

### Cleartext gRPC port in production (from v0.27)

`grpc.Serve` and `grpc.Server` (`contrib/grpc`) no longer treat `HTTP_H2C=true` as the opt-in for a cleartext gRPC port in production: that variable now concerns only the main HTTP server. A port without `ServerOptions.TLS` in production needs `GRPC_INSECURE_CLEARTEXT=true` (or `ServerOptions.InsecureCleartext: true`), otherwise boot fails with `grpc.ErrCleartextInProduction`. Set it only on a private network (Railway private networking) or behind a proxy that terminates TLS and speaks h2c; a Railway TCP proxy forwards raw bytes, so a public port there needs `ServerOptions.TLS`. Values other than `true`/`false` fail boot (`grpc.ErrInvalidInsecureCleartext`).

### OpenTelemetry metrics follow the generic endpoint (from v0.27)

`drivers/otel` now applies `OTEL_EXPORTER_OTLP_ENDPOINT` to metrics too, as the OpenTelemetry spec says (`OTEL_METRICS_EXPORTER` defaults to `otlp`): an app that sets only the generic endpoint starts exporting metrics to `<endpoint>/v1/metrics`. `OTEL_EXPORTER_OTLP_METRICS_ENDPOINT` still overrides it. If the collector accepts only traces, set `OTEL_METRICS_EXPORTER=none`; `OTEL_METRICS_EXPORTER=otlp`, which earlier versions needed, can stay or go. On Railway (`RAILWAY_ENVIRONMENT` or `RAILWAY_SERVICE_ID`) that `none` is unnecessary: the receiver accepts traces only, so metric export stays off unless `OTEL_EXPORTER_OTLP_METRICS_ENDPOINT` is set, even when the exporter is `otlp`. Logs there are JSON on stdout and stderr; resource and HTTP metrics are Railway's built-in metrics.

### i18n.Middleware returns an error

`i18n.Middleware(bundle, cfg)` returns `(func(http.Handler) http.Handler, error)` instead of panicking when `cfg` fails `MiddlewareConfig.Validate`. Apps that wire it by hand handle the error; `vukem.DefaultMiddleware`, `DefaultMiddlewareWith` and `APIMiddlewareWith` are unchanged.

```go
// before
r.Use(i18n.Middleware(bundle, i18n.MiddlewareConfig{}))
// after
locale, err := i18n.Middleware(bundle, i18n.MiddlewareConfig{})
if err != nil {
	return err
}
r.Use(locale)
```

Calls to `i18n.NewMiddleware`, which already returned the error, keep compiling; `go fix ./...` rewrites them to `i18n.Middleware`.

### Email verification needs the login (from v0.27)

The `install:auth` scaffold used to verify the address when the signed link was opened signed out. If someone signed up first with another person's address, the owner clicking that link verified the squatter's account (with the squatter's password). The link now needs the login of the account it verifies: signed out, it leads to `/login`, and the login comes back to the link (the intended URL) and verifies it; another signed-in account still gets 403. Apps generated before v0.27.0 keep the old behaviour until they re-run `vukem install:auth --force` (review the diff in a branch) or port it by hand:

```go
// routes/auth.go: before
r.Get("/email/verify/{id}", h.Verify).Name("verification.verify").Use(acc.Signer.Middleware())
// after
r.Get("/email/verify/{id}", h.Verify).Name("verification.verify").Use(required)
```

In `app/controllers/account/verification.go`, `Verify` takes the user from `auth.User[models.User](c, "web")` instead of loading it by id, answers 403 when `u.ID` differs from the `{id}` parameter, redirects an already verified user to `/dashboard`, checks the signature itself with `h.a.Signer.Verify(c.Request())` (on `signed.ErrExpired` it flashes the new `auth.verification_expired` message, added to `app/accounts/lang/*/auth.json`, and redirects to `/email/verify`; otherwise it logs `url.signature_invalid` and answers 403), then checks `email_hash` and calls `h.a.VerifyEmail(c.Context(), &u, c.Session().ID())` followed by `h.a.Web.RefreshSession(c)`. With `--social`, the callback in `routes/social.go` redirects to `web.SafeRedirect(c.Request(), target, "/dashboard")` with the `auth.IntendedKey` it pulls from the session, like `Login`. Generated tests that open the link signed out and expect a redirect to `/login` followed by a verified account now log in first (see `TestRegisterAndVerifyEmail` in a fresh scaffold).

### Inertia error pages (from v0.27)

With `vukem.WithInertia`, errors on Inertia visits (404, 403, 500…) render the page component `Error` with the props `status`, `title` and `message` instead of the raw HTML page in Inertia's modal. An app without that page breaks on every such error (the client cannot resolve the component); in development it logs `inertia error page not found` at boot. Pick one:

- add `resources/js/pages/Error.tsx` (`.vue`, `.svelte`; copy it from a new starter: `vukem new tmp --inertia react`), or point `inertia.Config{ErrorComponent: "Errors/Show"}` at an existing page;
- or keep the HTML page: `app.Router.Services().ErrorPage = nil` in your routes.

`web.Services.ErrorPage` is a `web.ErrorPageFunc` taking a `web.ErrorPage`; `vukem.WithInertia` sets it only when it is nil, before the routes run.

### Request headers capped at 64 KiB (from v0.27)

The app server and `vukem.NewHTTPServer` accept at most 64 KiB of request line and headers (`vukem.DefaultMaxHeaderBytes`, was Go's 1 MiB); larger requests get 431. The gRPC port of `contrib/grpc` (`grpc.Serve`, `grpc.Server`) uses the same cap, which also bounds gRPC metadata. If clients send larger headers (big cookies, tokens or metadata), set `HTTP_MAX_HEADER_BYTES` (4096–1048576; `grpc.Serve` reads it too) or `grpc.ServerOptions.MaxHeaderBytes`. A value outside that range fails boot.

### Authorization of value subjects (from v0.28)

`authz.Gate.Check` (and `c.Authorize`, `can` in templates) used to deny a `models.Post` value when only `authz.For[*models.Post]` was registered. It now calls the `*models.Post` policy with a pointer to a shallow copy, so `{{range .Posts}}{{if can "delete" .}}` works. Nothing breaks, but code or tests that expected that denial now get the policy's answer. Types with no policy for `T` or `*T` are still denied.

### ORM pagination capped at 100 per page (from v0.28)

`Query.Paginate` and `Query.CursorPaginate` clamp `perPage` to 1..`orm.DefaultMaxPerPage` (100); `Page.PerPage` and `CursorPage.PerPage` report the value used. A page that needs more rows calls `.MaxPerPage(n)` on the query. `api.Query` raises the bound to its `api.PerPage(def, max)` maximum and admin list pages to `Resource.PerPage`, so they need no change.

### Chunk reads by primary key (from v0.28)

`Query.Chunk` continues each batch after the last primary key seen instead of using `OFFSET`, so a callback that deletes or updates its rows no longer skips rows. It now returns an error when the query has its own `OrderBy`, `Limit` or `Offset`, or a `Select` without the primary key: drop those clauses, or stream with `Each` and `OrderBy`.

### Schema and rule naming fixes (from v0.28)

- `ForeignID(...).Constrained()` pluralises like the ORM (`category_id` → `categories`, was `categorys`). Migrations that already ran keep their tables; `migrate:status` may show `Ran (CHANGED since applied)` for a migration whose `Constrained()` target changed. On SQLite, which does not check that the referenced table exists, check such foreign keys point at the table you meant.
- `schema.Raw(sql, args...)` with arguments rebinds `?` for the dialect; a statement already written with `$1` still works, but one mixing `?` and `$n` now fails.
- `orm.Unique`/`orm.Exists` with `.Field(name)` name that field in the built-in message and look up `validation.attributes.<name>` instead of the column's translation.
- `drivers/mongo`: `mongo.ErrNotFound` answers 404 when returned from a handler (was 500), and `Coll.All` returns an empty slice (JSON `[]`) instead of nil. Remove manual mappings of `mongo.ErrNotFound` to `errs.ErrNotFound` if you like; they keep working.

### Auth hardening (from v0.28)

- `vukem install:auth --social x` (alone or in a list) now fails with exit code 2: X sends no email address, and the scaffold creates and links accounts only by a provider-verified email, so every new X sign-in answered 422. Drop `x` from the list. Apps that already scaffolded it keep their code; link X to signed-in accounts in your own code if you need it.
- `jwt.Guard` answers a key set outage (a `RemoteJWKS` fetch failing with no cached key, now `jwt.ErrKeysUnavailable`) or a user lookup error other than not found with 503 instead of 401, and `auth.Required` no longer tries the next guard after it. Clients that retried on 401 with a new login now see 503 during an outage. Custom key sets wrap `jwt.ErrKeysUnavailable` for their own outages; custom guards outside package `auth` can implement `auth.FailClosedChecker` to get the same behaviour.
- Token and JWT guards accept the `Bearer` scheme in any case (`bearer <token>`), as RFC 7235 requires (`auth.BearerToken`).
- `install:auth --2fa` apps generated before v0.28.0 regenerate recovery codes without the password. Port it by hand: in `routes/two_factor.go` add `confirm` to the middleware of `two-factor.recovery-codes`; in `RegenerateRecoveryCodes` (`app/controllers/account/two_factor.go`) parse `requests.ConfirmPasswordSchema` and check `h.a.Hasher.Verify(u.Password, in.Password)` like `Disable` (log `auth.2fa_failed` with `stage=recovery_codes`); add a current-password field to the regenerate form of the settings page, and send `password` in tests that post to `/user/two-factor/recovery-codes`.
- `install:auth` apps generated before v0.28.0 delete API tokens when an email is verified or a provider-verified social sign-in links an unverified account. To keep them listed as revoked, replace the `DELETE FROM access_tokens` statement of `revokeAccess` (`app/accounts/users.go`) with `tokens := auth.NewTokens(ex)` and `tokens.RevokeAll(ctx, id)` (copy `Now` and `Log` from `a.Tokens`). Tests that expect the rows to be gone check `revoked_at` instead.

### storage.PutUploaded needs Types (from v0.28)

`storage.PutUploaded` with an empty `UploadRules.Types` used to accept any content; it now fails with `storage: UploadRules.Types is required` (a 500, like a missing `MaxSize`). List the types you accept, for example `storage.UploadRules{MaxSize: 10 << 20, Types: []string{"application/pdf"}}` or `storage.Images(maxSize)`.

### Mail tags are checked for every transport (from v0.28)

`Mailer.Render` (so every `Send`) now refuses tags with an empty name or a line break or colon in the name or value on every transport, not only SMTP (`mail: tag contains a line break or colon`). The Resend transport also refuses tags outside Resend's charset (ASCII letters, digits, `_`, `-`, at most 256 characters) before the request, where Resend used to answer 422. Rename such tags, for example `order:42` to `order-42`.

### Broken mail settings fail at boot (from v0.28)

With `MAIL_MAILER` set, `app.Boot` (so `serve`, workers and every command, `migrate` included) fails when the transport cannot work: `resend` without `RESEND_API_KEY`, `mailtrap` without `MAILTRAP_API_TOKEN` or with a negative `MAILTRAP_INBOX_ID`, or an unknown name. These used to fail on the first `app.Mailer()` call. Set the variable, or remove `MAIL_MAILER` where the process sends no mail.

### Idempotency replays only representation headers (from v0.28)

`api.Idempotency` now replays `Content-Type` plus `IdempotencyOptions.ReplayHeaders` (default `Content-Language`, `Content-Disposition`, `Content-Location`, `Location`, `ETag`, `Last-Modified`, `Link`); other headers come from the repeat request's own middleware. List any custom response header a client reads on a replay in `ReplayHeaders`.

### OpenAPI operation ids and security schemes (from v0.28)

Plain (non-`api.Register`) routes inside a named group now take their own name as `operationId` (`me` instead of `api.v1.me`), like typed routes: regenerate clients (`vukem codegen:client`) and rename calls such as `APIV1Me` to `Me`. A name in `api.Op.Security` that is neither `bearer` nor declared in `openapi.Info.SecuritySchemes` now fails `App.OpenAPI` / `openapi.Build` (`openapi.ErrUnknownSecurityScheme`) and makes `openapi.Generate` panic; declare the scheme. Two routes in one document whose own names match (`api.v1.index` and `api.v2.index` both become `index`) now fail with `openapi.ErrDuplicateOperationID`: serve one document per version (`vukem.OpenAPIOptions.PathPrefix`) or rename a route. The document is built on demand, so these errors show on the first `/openapi.json` request, `openapi:export` or `codegen:*`; a test calling `app.OpenAPI()` catches them in CI.

### GraphQL: introspection, Validate errors and unresolvable fields (from v0.28)

- `Schema.Handler` rejects `__schema` / `__type` unless `HandlerConfig.Introspection: true`; `graphql.Serve` keeps enabling it outside production.
- A `Validate()` error on an arguments struct is mapped like a resolver error: a plain `errors.New` now answers `Internal server error`. Return `z.FieldError`, `errs.New(422, ...)` or `graphql.NewError` for client messages.
- `graphql.New` fails when an object field without a resolver has no matching Go field on the type behind it; bind a resolver or add the field (or its `json` tag).

### Body limits are checked on read (from v0.28)

`middleware.BodyLimit` no longer answers 413 before the chain runs when the declared `Content-Length` is over the limit: the first read of the body fails instead (before any byte is consumed), and `c.Input()`, `c.BindJSON`, `web.Parse` and `upload` answer 413. The innermost limit wins, so a route's `BodyLimit` or `upload.Rules.MaxSize` can now raise the router-wide 10 MiB. A handler that never reads the body no longer gets 413; a handler that reads `r.Body` itself sees an `*http.MaxBytesError`, as it already did for chunked bodies. Drop any workaround that kept uploads under 10 MiB.

### c.BindJSON rejects unknown fields (from v0.28)

`c.BindJSON` now does what its documentation said: a JSON key that the target struct does not have answers 422 with a field error (`The field is not allowed.`) instead of being dropped. Clients that send extra keys must stop, or the handler must decode leniently: third-party payloads such as webhooks should use `json.NewDecoder(c.Request().Body).Decode(&v)`, and typed handlers (`web.Parse`, `z` schemas) keep ignoring unknown keys. Maps (`map[string]any`) accept any key as before.

### Group root routes are exact (from v0.28)

`g.Get("/", h)` inside a group (`r.Group("/admin", ...)`) registers `GET /admin/{$}`: it answers `/admin/` (and redirects `/admin` there) but no longer every path below it, so `/admin/anything` is a 404 instead of the dashboard. A group that relied on the catch-all must register it explicitly: `g.Get("/{path...}", h)`. `g.Get("", h)` still serves `/admin` only.

### c.Status no longer sends the status at once (from v0.28)

`c.Status(code)` used to write the status line immediately, so the headers of the helper that followed (`Content-Type`, `Location`, `X-Inertia`) were lost. It now records the status, and the next write that would send `200` (`c.JSON(200, v)`, `c.Render`, `c.View`, `inertia.Render`, a plain `Write`, a flush) sends it instead, with its headers. Any other status wins over it: `c.Status(201).Redirect("/x")` answers 302, `c.Status(201).NoContent()` 204. A handler that returns nil without writing still sends the status; an error or a panic answers with its own status. Code that relied on `c.Writer().Written()` being true right after `c.Status` must check it after the body is written; drop any `ResponseWriter` wrapper written to rewrite the status.

### Custom template functions cannot replace built-ins (from v0.28)

`view.New` (and so `vukem.WithViewFuncs`) fails when `view.Config.Funcs` uses the name of a built-in template function (`route`, `asset`, `csrfField`, `csrfToken`, `cspNonce`, `old`, `error`, `errors`, `flash`, `vite`, `htmxScript`, `t`…): `view: Config.Funcs "csrfField" replaces a built-in template function`. Rename your function; a replaced `csrfField` or `cspNonce` could drop the CSRF token or the CSP nonce.

### Telegram is never nil, and info means info (from v0.28)

`app.Telegram` is now a disabled handler when `TELEGRAM_BOT_TOKEN` or `TELEGRAM_CHAT_ID` is missing, instead of `nil`: `Send` and `Contact` drop the message and `SendSync`/`ContactSync` return `telegram.ErrDisabled`. Replace `app.Telegram == nil` checks with `!app.Telegram.Configured()`; `!= nil` guards can go. `TELEGRAM_MIN_LEVEL=info` now forwards info records (it used to forward only errors, because `slog.LevelInfo` is the zero value); a standalone `telegram.Config` needs `MinLevelSet: true` for `MinLevel: slog.LevelInfo`.

### Webhook dedupe keys are namespaced (from v0.28)

`webhook.Dedupe` keys now include a namespace (`DedupeOptions.Namespace`, default the matched route pattern, else one fixed namespace), so providers that reuse event ids no longer drop each other's deliveries. Keys written by an older version are not found after the upgrade: a redelivery of an event handled just before the deploy runs once more, so keep handlers idempotent across the deploy. Provider prefixes you added in the `id` function keep working and can stay.

### contrib/stripe refuses params it cannot encode (from contrib/stripe v0.4)

Every map with string keys and every slice in `stripe.Params` is now form-encoded at any depth (`[]map[string]any` used to be sent as `fmt.Sprint` text). A struct, func or map with non-string keys fails the call with `unsupported type` instead of sending its text: convert it to `stripe.Params` first. NaN and ±Inf, and nesting deeper than 32 levels (a cyclic map), fail the same way; a `[]byte` is sent as a string.

### i18n plurals need "other" (from v0.28)

A catalog object whose keys are all plural categories (`zero`, `one`, `two`, `few`, `many`) but has no `other` now fails `i18n.Load` and `Bundle.Add` with `plural forms need "other"`; it used to become a group of keys (`posts.count.one`) and the message went missing at runtime. Add the `other` form.

### vukemtest session assertions see stored nil values (from v0.28)

`AssertSessionHas(key)` and `AssertSessionMissing(key)` now check whether the key exists. A key stored with a `nil` value used to count as missing; now `AssertSessionHas` passes for it and `AssertSessionMissing` fails. A test that relied on `Put(key, nil)` looking absent should assert `AssertSessionMissing` only after `Forget(key)`, or check the value with `Response.Session()`.

### `@file:` in the process environment (from v0.28)

A process environment variable whose value starts with `@file:` is now read from the named file, like a `.env` value (Docker and Kubernetes secrets). Before, the text was used literally. A variable that really holds text starting with `@file:` must be written `@@file:...` (one leading `@` is removed). A reference that cannot be read (missing file, directory, device, more than 1 MiB) now stops the boot.

### Upload rules refuse types the detector cannot see (from v0.30)

`upload.Rules.Types` is matched against the type detected from the file's content, and a type that detection never produces (AVIF, HEIC, HEIF, JPEG XL, TIFF) used to be accepted and then rejected every such file. `upload.Receive` and `upload.Save` now return `upload.ErrUndetectableType` for it. Keep `Types` within `upload.DetectableTypes()`, and check the other formats with a detector of your own.

### Memory cache locks fail closed when full (from v0.32)

On the in-process `cache.Memory` store, held locks may fill at most half of `MaxEntries`; past that, acquiring a new lock reports false instead of evicting a held one. An app that takes many locks on that store raises `MaxEntries` or keeps its locks in Redis.

### A failed concurrent index stops migrate on PostgreSQL (from v0.34)

A `NoTransaction` migration whose `CREATE INDEX CONCURRENTLY` failed leaves an `INVALID` index; the retry used to skip it with `IF NOT EXISTS` and record the migration. `vukem migrate` now fails naming the index: run `DROP INDEX CONCURRENTLY` on it, fix the cause and migrate again.

### Unique jobs need a driver that enforces them (from v0.38)

Dispatching a job with `queue.Unique` to a driver that cannot refuse a duplicate (one that is not a `queue.Uniquer`, such as the Redis queue) now fails with `queue.ErrUniqueUnsupported` instead of storing a duplicate. Memory, Database and Fake support it; drop `Unique` or switch to the database queue for those jobs.

### The ORM binds times in UTC (from v0.39)

Every `time.Time` the ORM binds (`Where`, `WhereIn`, `WhereBetween`, `Set`, model fields and timestamps) is converted to UTC. Columns that keep the clock reading without a zone (MySQL `DATETIME`, PostgreSQL `TIMESTAMP`, SQLite text) now receive the UTC reading, so rows an earlier version wrote in another zone sort and compare apart from new ones: convert them to UTC once with a migration. For `db.ExecContext`, call `t.UTC()` yourself.

### Bulk Update and Delete refuse Limit, Offset and OrderBy (from v0.40)

`Query.Update` and `Query.Delete` used to ignore `Limit`, `Offset` and `OrderBy` and write every matching row. They now return an error. To write a bounded set, select the keys first (`Pluck`) and filter with `WhereIn`.

### Cron day fields starting with * are combined with AND (from v0.40)

A day-of-month or day-of-week field that starts with `*`, such as `*/2`, now combines with the other day field using AND, as in Vixie cron. `0 0 */2 * 1` runs on odd days that are Mondays; before, it ran on every odd day and on every Monday.

### Scheduled tasks run once across DST changes (from v0.40)

In a time zone with daylight saving time, a task with a fixed hour (such as `30 1 * * *`) used to run twice on the day the clock goes back and not at all on the day it skips that hour. It now runs exactly once on both days, at the first minute after the jump when its time is skipped. Tasks with a wildcard hour still follow real time.

### The HTTP drain closes what it cannot drain (from v0.40)

When in-flight requests outlast `ShutdownTimeout`, `HTTPServer.Run` now closes the remaining connections, which cancels their request contexts, before providers such as the database pool shut down. Its error still wraps `context.DeadlineExceeded`: match it with `errors.Is`, not `==`.

### Rate limit windows of zero or less are one second (from v0.40)

`ratelimit.NewMemory`, `ratelimit.NewMemoryBurst` and the Redis `RateLimiter` treat a window of zero or less as one second. Before, the memory limiter panicked on every request and the Redis limiter denied all of them.

### Bus.Shutdown drops async listeners dispatched while it closes (from v0.40)

No async listener starts after `Bus.Shutdown` returns: one dispatched while the bus is closing is dropped with a warning log instead of running against providers that are already shut down.

### GraphQL APQ stores only valid POSTed documents (from contrib/graphql v0.5)

Automatic persisted queries no longer store a document that fails to parse or validate, one sent over GET, or one larger than `PersistedQueries.MaxDocumentBytes` (64 KiB by default). A client that registered queries over GET must register them with POST.

### orm.Restore reports a record that is not trashed (from v0.40)

`orm.Restore` now returns `orm.ErrNotFound` when no trashed row matches the key (the record is live or does not exist), instead of succeeding and clearing `DeletedAt` on the model. Handlers that treated `Restore` as idempotent must handle the error.

### i18n plural forms follow the locale of the fallback message (from v0.40)

When a key falls back to another locale, `T` and `Translator` pick the plural form with the rules of the locale the message came from, not the requested one: `ru` falling back to `en` with `count` 21 yields the English `other` form.

### z MultipleOf is exact for integers and tolerant for floats (from v0.40)

`MultipleOf` checks integers with integer arithmetic, so values above 2^53 are no longer rounded, and compares floats by quotient with a relative tolerance of 1e-9, so `Float().MultipleOf(0.01)` accepts `0.07`. The generated JSON Schema is unchanged.

### Apps generated by install:auth: add the per-IP login limit (from v0.40)

New `install:auth` apps limit login attempts per IP (30 a minute) on top of the per email and IP and per account limits. In an app generated before, add to `routes/auth.go`: `loginByIP := ratelimit.Middleware(limiters("login.ip", 30, time.Minute), ratelimit.ByIP)`, and use it on the login route: `r.Post("/login", h.Login).Use(guest, loginByIP, throttle, perAccount)`.

### Apps generated by install:auth: keep the reset token out of the logs (from v0.40)

New `install:auth` apps mark the password reset token as a secret route parameter, so request logs, error logs and security events show `{token}` instead of its value. In an app generated before, add `.SecretParams("token")` to the reset route in `routes/auth.go`: `r.Get("/reset-password/{token}", h.ShowReset).Name("password.reset").Use(guest).SecretParams("token")`.

### social.Allow refuses only with ErrNotAllowed (from v0.40)

Any error returned by `Social.Allow` used to refuse the sign-in (403). Now only `social.ErrNotAllowed`, or an error wrapping it, refuses; any other error is a failed check that answers 503 and is logged as a warning. Return `social.ErrNotAllowed` to refuse, and the lookup error as is when the check cannot run:

```go
s.Allow = func(ctx context.Context, u social.User) error {
	if !allowed(u) {
		return social.ErrNotAllowed
	}

	return nil
}
```

### TOTP periods must be whole seconds (from v0.40)

`totp.Options.Period` must be whole seconds and at least one second: `Code` returns an error, `Validate` returns false and `URI` returns an empty string otherwise. `QR` and `QRMatrix` refuse empty text with `totp.ErrEmpty`, so such an enrollment fails instead of showing a blank QR code.

### contrib/imaging applies the JPEG EXIF orientation (from contrib/imaging v0.2)

Thumbnails of JPEG sources are rotated according to their EXIF orientation before scaling. Apps that rotated thumbnails themselves must stop, or images rotate twice. PNG, GIF and WebP orientation is still ignored.

### SMTP_INSECURE is refused in production (from v0.40)

With `APP_ENV=production`, `MAIL_MAILER=smtp` and `SMTP_INSECURE=true` are a mailer error unless `SMTP_HOST` is `localhost` or a loopback IP. The setting is meant for local mail catchers; a production SMTP server must offer STARTTLS or implicit TLS.

### PostgreSQL connections to remote hosts verify TLS by default (from drivers/postgres v0.7)

A `postgres://` or `postgresql://` `DATABASE_URL` whose host is not loopback or a unix socket gets `sslmode=verify-full` when it has no `sslmode`. Before, pgx's default (`prefer`) fell back to plaintext without a word, so a server without TLS, or with a certificate that does not verify, now fails at boot. On a trusted private network, say so in the URL with `?sslmode=disable`; other explicit values pass through unchanged.

### Redis connections to remote hosts require TLS (from drivers/redis v0.6)

A plain `redis://` URL to a host that is not loopback is refused. Use `rediss://`, or, on a trusted private network, add `?insecure_plaintext=true` to the URL. `rediss://`, `unix://`, `localhost` and loopback IPs are not affected.

### ssg replaces the output directory (from v0.41)

`ssg.Generate` and `ssg:generate` now render into a sibling temporary directory and replace the output directory once every page succeeded, so pages that no longer exist disappear and a failed run changes nothing. A directory with other files and no `.vukem-ssg` marker (including one written by an older version) is refused with `ssg.ErrNotGenerated`: empty it once, or pass `Options.NoClean` / `-no-clean` to keep writing in place. A symbolic link as the output directory is refused with `ErrEscape` unless `NoClean` is set. On error the report is empty unless `NoClean` is set.

### MongoDB duplicate keys answer 409 (from v0.41)

A write that violates a unique index (`Insert`, `InsertMany`, `UpdateOne`, `UpdateMany`, `ReplaceOne`) now returns an error that matches `mongo.ErrDuplicate` and implements `HTTPStatus()`, so a handler that returns it answers 409 instead of 500. The driver's own error is still reachable with `errors.As`. Code that matched the raw driver error keeps working; code that expected a 500 for a duplicate key needs to expect 409.

### queue:failed lists the newest 100 by default (from v0.41)

`queue:failed` now stops at the newest 100 failed jobs (a `LIMIT` in the query) instead of loading every payload. Scripts that need the full list pass `-limit 0`. The Redis driver does not implement `queue.FailedPager`, so it still lists everything.

### orm.Update skips trashed rows (from v0.41)

`orm.Update` no longer writes a row whose `deleted_at` is set on a model with `orm.SoftDeletes`: it returns `orm.ErrNotFound`, as it does for a missing row. To change a trashed row on purpose, use `orm.QueryOf[T](db).OnlyTrashed().Where("id", id).Update(ctx, orm.Set{"title": "x"})`. To write only some columns of a model (and not overwrite what another writer changed), use the new `orm.UpdateOnly(ctx, db, &m, "title")`.

Related changes in the same release: a `database.Dialect` that is not one of the built-in ones must implement `database.Capable` (`Capabilities() database.Capabilities`), or `database.Open` rejects its driver and the ORM returns an error; and `ILIKE` on SQLite, which the engine rejects, is now sent as `LIKE` like on MySQL.

### MySQL refuses clientFoundRows=false (from v0.41)

`drivers/mysql` counts the rows an `UPDATE` matches, not the rows it changes (`clientFoundRows=true`, the default), because the ORM tells a missing row from a stale one by that count: with changed-rows counting, an update that sets the values a row already has looks like a missing row. A `DATABASE_URL` with `clientFoundRows=false` is now refused when the database opens, with `ErrInvalidURL`: `clientFoundRows must be true (the default); remove clientFoundRows=false from the URL`. What to do: remove the parameter from the URL (and from any `DSN`-style setting that builds it). Nothing changes for a URL that never set it, and PostgreSQL and SQLite are not affected.

### OpenAPI constraints come from z (from v0.41)

The OpenAPI document now takes its constraint keywords from `z`, the engine that validates the request, instead of a second parser in `openapi`. Generated clients (`codegen:client`, `codegen:types -zod`) change where the two used to disagree:

- `omitempty` on a string with a rule: the empty string is allowed next to the rule (`anyOf` with `{"enum": [""]}`).
- `default=V`: the document carries `default`.
- `ulid`: `^[0-7][0-9A-HJKMNP-TV-Za-hjkmnp-tv-z]{25}$` (lowercase accepted, as the server does).
- `alpha` and `alphanum`: any Unicode letter or digit (`\p{L}`, `\p{N}`), as the server does.
- `numeric`: an optional sign and decimals (`^-?\d+(\.\d+)?$`), as the server does.

A route registered with `api.RegisterWith` is now described by its schema: the schema's rules replace the tag-derived ones on the top-level inputs and `required` follows it, so a key the schema makes optional is optional in the document. A nullable (pointer) field with `omitempty` now also allows `null` next to its rules. Keys of the input type that the schema does not list are no longer `required` (the server does not check them). Regenerate the clients after the upgrade.

### Renamed or removed APIs (public API review)

The pre-freeze API reviews are recorded in [docs/api/review.md](../api/review.md) (with the full `apidiff` report next to it) and [docs/v1-api-review.md](../v1-api-review.md). Identifiers renamed after the first review kept a deprecated alias marked `//go:fix inline` for five releases, until `v0.26` removed the aliases: run `go fix ./...` on `v0.25` or earlier before the upgrade, or rename by hand.

### Chained .env references and cycles (from v0.41)

A `.env` value that references another file value now gets that value expanded too: with `A=${B}`, `B=${C}`, `C=x`, `A` is `x` (it used to be the text `${C}`). A cycle (`A=${B}`, `B=${A}`) is a load error naming the key, and so is a value that expands past 64 KiB. Values set in the process environment still win and are not expanded.

### Migrations need two connections on PostgreSQL and MySQL (from v0.41)

The migration lock holds one connection while the migrations run on the pool, so a pool limited to one connection waited forever. `Migrator` now refuses it up front with `schema: migrations need at least 2 connections to hold the lock; raise DB_MAX_OPEN`. Raise `DB_MAX_OPEN` to 2 or more (or leave it unset).

### migrate refuses a destructive migration in production (from v0.41)

With `APP_ENV=production`, `vukem migrate` reads what each pending migration would do, without running it, and stops before the first one that drops data: `DROP TABLE`, `DROP COLUMN` (also inside a combined `ALTER TABLE`, and in statements written with `Schema.Raw`) and, on SQLite, a `Rebuild` whose definition leaves out a column the table has. The error is `refusing to run a destructive migration in production without --allow-destructive: <id> would <what>`, and nothing runs. `TRUNCATE` and `DELETE FROM` are not detected, and a `Schema.HasTable` guard around a drop is not evaluated, so the drop is reported anyway.

What to do: review the migration, take a backup, then run `vukem migrate --allow-destructive` in the release phase (outside production the flag changes nothing). A deploy that runs plain `vukem migrate` (a Dockerfile `CMD`, a Procfile `release:` line, a CI job with `APP_ENV=production`) fails on such a migration until it passes the flag. `vukem migrate:status` lists what is pending.

### api.PerPage normalizes its bounds (from v0.41)

`api.PerPage(def, max)` raises values below 1 to 1 and caps `def` at `max`; `PerPage(20, 0)` used to produce `per_page = 0`.

### CrossOrigin routes match the overridden method (from v0.41)

`MethodOverride` now runs before the `MiddlewareOptions.CrossOrigin` routes, so a form `POST` with `_method=PUT` is matched against `PUT /path` patterns instead of `POST /path`. A `POST` pattern no longer covers a request that the router will treat as `PUT`, `PATCH` or `DELETE`: list the overridden method in its own `CrossOriginRoute` if browsers' forms must reach it.

### GraphQL custom scalar Parse errors are masked (from v0.41)

A custom scalar's `Parse` error reaches the client only as client-safe text: the message of a `*graphql.Error`, the message of a 4xx error that is a plain `StatusCoder` (any other 4xx gives the status text), or `Invalid input` for a validation error; any other error, and any 5xx, is reported as `<Scalar>: invalid value`. Return `&graphql.Error{Message: "..."}` from `Parse` to keep a client message.

### GraphQL Cost must not be negative (from v0.41)

`graphql.Cost(n)` with a negative `n` now makes `graphql.New` fail instead of lowering the query complexity. `Cost(0)` still means the default of 1. A directive argument with an output type or an invalid default value now fails `graphql.New` too.

### GraphQL complexity counts explicit null and the largest page size (from v0.41)

For the complexity limit, a `first`, `last` or `limit` argument passed as an explicit `null` (literal or variable) now costs the worst case instead of 1, and the largest of the three counts instead of the first one above 1. An omitted argument still costs its SDL default. Clients that send `null` to mean "the default" should omit the argument.

### An unset `APP_ENV` now means production (from v0.41)

`APP_ENV` unset or empty used to mean `development`; it now means `production`, in `Config.Env`, in the `.env.<env>` files that are read and in `config.Source.Env`. An app that ran without `APP_ENV` now gets the production checks and defaults: `APP_KEY` is required, session cookies are `Secure` (they are not sent over plain `http://localhost`), the Vite dev server and view reload are off, the debug error page is off, and destructive commands need `-force`. The `vukem new` scaffolds already write `APP_ENV=development` to `.env`, and the generated `Dockerfile` sets `APP_ENV=production`.

What to do: set `APP_ENV=development` (or `test`) in `.env` and in the environment of local runs and CI, and `APP_ENV=production` on servers. In tests, name the environment explicitly: `vukemtest` already sets `test`, and `config.MapSource` needs `"APP_ENV": "test"` when the test relied on the old default. `vukem doctor` warns when `.env` does not set it.

### OIDC and JWKS need https and a matching issuer (from v0.41)

`social.OIDC` (so `Google`, `Microsoft`, `LinkedIn` and `Apple`) and `jwt.RemoteJWKS` now refuse a plain `http` issuer, discovery endpoint or JWKS URL, unless the host is `localhost` or a loopback address. The `issuer` of the discovery document must also equal the configured issuer (a `{tenantid}` placeholder only has to keep the host). An identity provider that is reached over `http` on a private network (a Keycloak in a Docker network, say) needs `.InsecureHTTP()` on the provider or `InsecureHTTP: true` on the `RemoteJWKS`; prefer putting it behind https.

### Social sign-in state cookie is `__Host-social_<provider>` (from v0.41)

The state cookie of a social sign-in is named `__Host-social_<provider>` (Secure, `Path=/`, no `Domain`); with `InsecureCookies` it keeps `social_<provider>`. A sign-in that was started before the deploy fails once and the user starts it again. Code or tests that read the cookie by its old name need the new one.

### Recovery codes have 80 bits (from v0.41)

`totp.RecoveryCodes` returns codes like `ABCD-EFGH-IJKL-MNOP` (80 random bits) instead of `ABCDE-FGHIJ`. Codes already issued keep working, since only the generator changed. Screens that lay the codes out in a fixed-width grid, and tests that match the old shape (`[A-Z2-7]{5}-[A-Z2-7]{5}`), need updating.

### Argon2id hashers limit concurrency (from v0.41)

A hasher from `hash.Argon2id` (and `hash.Default`) runs at most `Argon2Params.MaxConcurrent` computations at once (default `runtime.GOMAXPROCS(0)`); the others wait. Create one hasher and reuse it: each call to `hash.Default()` returns a new hasher with its own limit.

### upload.SanitizeName follows the shared filename rules (from v0.41)

`upload.SanitizeName` now applies the same rules as the `Content-Disposition` sanitizer of `export` and `web.Ctx.Download`. Compared with before: `"`, `<`, `>`, `:`, `|`, `?` and `*` become `_` instead of being removed (`a"b.txt` gives `a_b.txt`) or kept; C1 control characters and U+2028/U+2029 are removed; trailing dots and spaces are removed; a Windows device name gets a leading `_` (`NUL.txt` gives `_NUL.txt`), so the result can be one character longer than the 200 limit. Nothing that was removed before is kept now.

What to do: names you already stored are not rewritten. Check code and tests that compare the result with a fixed string, and anything that treats the result as a storage key: it is for display and `Content-Disposition`, never for paths (generate your own key and keep the sanitized name as metadata).

### middleware.SecureHeaders without TrustedProxies never trusts X-Forwarded-Proto (from v0.41)

With `TrustForwardedProto` set and an empty `TrustedProxies`, `middleware.SecureHeaders` used to accept `X-Forwarded-Proto: https` from any peer. It now trusts no peer, so no request is treated as HTTPS through that header. `SecureHeadersConfig.Validate` and the app boot already rejected this combination; only code that built the middleware by hand without validating is affected. Set `TrustedProxies` to the proxies in front of the app.

### Problem `type` follows `APP_PROBLEM_BASE_URL` for every status (from v0.41)

With `APP_PROBLEM_BASE_URL` set, only validation problems got a `type` (`<base>/validation`); every other problem was `about:blank`. Now a problem without a `type` of its own gets `<base>/<status>`, with the status text in lower case and dashes: `https://api.example.com/problems/not-found`, `/internal-server-error`, `/im-a-teapot`. A client that compared `type == "about:blank"` for those problems has to compare the status instead, or the new URI. A `type` set with `HTTPError.WithType` or by a `ProblemDecorator` is unchanged, and without `APP_PROBLEM_BASE_URL` nothing changes.

### APP_PROBLEM_BASE_URL is validated at boot (from v0.41)

The value goes into the `type` member of every problem, so the app now refuses to boot with one that is not an `http` or `https` URL with a host, or that carries credentials, a query, a fragment, whitespace or control characters. The error is `vukem: APP_PROBLEM_BASE_URL must be an http or https URL with a host and no credentials, query or fragment (for example https://errors.example.com/problems); fix it or unset it`; it does not repeat the value. Trailing slashes are dropped (`https://x.example/problems/` and `https://x.example/problems` give the same `type`). What to do: check the variable in every environment, including CI and staging, before the deploy; a `javascript:` or `data:` value, or a bare `/problems` path, now stops the app from starting.

### Validation problems carry `issues`, a reserved member (from v0.41)

The `422` `application/problem+json` of a validation error keeps its `errors` member and gains `issues`: each problem with its `path`, `code`, message `key`, `params` and `on` (where the value came from: `body`, `query` or `params`). Clients that read `errors` need no change, and so does the Inertia Precognition answer, which gains the same member next to `message` and `errors`. The generated OpenAPI document and clients describe it.

`issues` is now a reserved member name, like `errors`: an extension of that name (`HTTPError.WithExtension("issues", ...)` or `Problem.Extensions`) is ignored. Rename it before you upgrade.

### z.Slice and z.Map are generic (from v0.41)

`z.Slice` and `z.Map` now return generic schemas, `z.SliceSchema[E]` and `z.MapSchema[V]`, that implement `z.Schema[[]E]` and `z.Schema[map[string]V]`. `Parse` returns the typed value instead of `any`, so a slice or map can go to `web.Parse`, `z.ParseJSON` and any other place that takes a `z.Schema[T]`, and they gain `Check`, `Refine`, `Transform`, and (for `Map`) `Default`, `Message` and `Describe`. Calls such as `z.Slice(z.String().Max(20)).Max(5)` compile unchanged: Go infers `E` from the element schema.

```go
// before: Parse returns any
tags, err := z.Slice(z.String()).Max(5).Parse(in)
list := tags.([]string)

// after: Parse returns []string
tags, err := z.Slice(z.String()).Max(5).Parse(in)
limits, err := z.Map(z.Int().Positive()).Max(10).Parse(in) // map[string]int
```

What breaks, and what to do:

- `Parse` of a slice or map schema returns `[]E` or `map[string]V`: drop the `.([]E)` type assertion.
- `SliceSchema.Default` takes `[]E`, and a value of another type is a compile error instead of a panic at boot.
- `z.SliceSchema` and `z.MapSchema` need their type argument when named in a declaration (`z.SliceSchema[string]`), and a type assertion or type switch to the old non-generic `z.SliceSchema` or `z.MapSchema` (for instance on a `z.AnySchema`) no longer compiles: assert to `z.SliceSchema[E]` or `z.MapSchema[V]`, or to `z.Schema[[]E]` or `z.Schema[map[string]V]`.
- A slice or map schema must be built from a `z.Schema[E]`; an element that is only an `AnySchema` no longer fits.

Every other schema also got the modifiers it lacked: `Transform` on `Bool`, `Time`, `Enum` and `JSON`, `Default` on `Struct` and `JSON`, `Message` on `Struct`, and `Nullable`, `Default`, `Refine`, `Transform`, `Message` and `Describe` on `Custom`. Only `z.File()` stays without `Nullable`, `Default` and `Transform`.

### The TypeScript client returns `{ data, error, status }` (from v0.41)

`vukem codegen:client` (and `openapi.TypeScriptClient`) now emit the result style: every method resolves to `{ data, error, status, headers, response }` and a non-2xx response is the `error` value, narrowed by status, instead of an `ApiError` thrown. A failed `fetch` still rejects. Methods also take an optional `CallOptions` (`{ signal, headers }`), and `createClient` takes `onRequest`, `onResponse` and `throwHttpError`.

To keep the previous behavior, regenerate with `-style throw` (`vukem codegen:client -style throw`, or `openapi.TypeScriptClientWith(doc, openapi.ClientOptions{Style: openapi.StyleThrow})`). The header of the file records the flag, so `vukem codegen` keeps it. To adopt the new style instead, replace `try { const x = await api.m(...) } catch (e) { if (e instanceof ApiError) ... }` with `const { data, error } = await api.m(...)`; `ApiError` stays exported, and `createClient({ throwHttpError: true })` makes a result-style client throw it. `-style throw` cannot be combined with `-tanstack`, whose helpers need the result style.

Generated clients that you commit must be regenerated, or a drift check fails: run `vukem codegen` (it regenerates the generated files that exist, with the flags their header records, and `vukem serve` runs it after each build), and add `-style throw` to every script, CI step or `package.json` command that calls `vukem codegen:client` if your code still relies on a thrown `ApiError`. `vukem codegen -check` fails when a generated file is stale, which is what to run in CI.

### inertia.Config.SharedType fails closed (from v0.41)

`inertia.Config.SharedType` (a struct that describes every shared prop, used by `vukem codegen:pages`) is optional and new, so this applies only to apps that set it. With it set, `inertia.New` refuses a key of `Config.Shared` that the struct does not declare (`inertia: shared prop "<key>" is not a field of Config.SharedType`), and a request whose page would send a key added with `inertia.Share` that the struct does not declare answers `500` instead of sending an untyped prop. A dotted key (`auth.user`) is checked by its first segment, and `errors` is always allowed. What to do: add every shared prop to the struct before you turn `SharedType` on (`vukem codegen:pages` then types it), or leave `SharedType` unset to keep the old behavior.

### Generator output lines start with a fixed prefix (from v0.41)

Every line that a `make:*` generator prints now starts with `created`, `updated`, `next:` or `note:`, except the indented continuation lines of a snippet or of the `email export` block that follow a `next:` line. A script that parses the output must expect `next: add vukem.WithAppSeeders(...)` instead of `add vukem.WithAppSeeders(...)`, `next: could not update <file> automatically; add this to <Func>():` instead of `could not update ...`, and one `next:` line per step of `make:mail --react` instead of the `next steps:` block. `vukem doctor` also reports `go_version` and fails an `APP_ENV` outside `development`, `test` and `production`.

### omitempty on any, map and time.Time fields

`validate:"omitempty,..."` on a field of type `any`, `map[string]any` or `time.Time` used to be ignored without a word; `z.FromTags` (and so `api.Register`) now refuses it at boot, as it already did for numbers and lists. Remove `omitempty` from those fields, or make the field a pointer.

### database.DB, database.Tx, schema.Schema and database.Driver gained a function field (from v0.41)

`database.DB` and `database.Tx` hold the driver's unique violation check, a function, so the struct values are no longer comparable: comparing two of them with `==` or using one as a map key does not compile. Compare the pointers (`*database.DB`, `*database.Tx`), which is what `database.Open` returns and `DB.Tx` passes to its function. `database.Driver` gained `IsUniqueViolation`; a driver built with an unkeyed struct literal must name its fields.

`schema.Schema` has the same change (it holds a function for `Rebuild` and the destructive-migration check): a value cannot be compared or used as a map key. A migration receives a `*schema.Schema`, so compare pointers there too.

### MySQL duplicate entries answer 409 (from drivers/mysql v0.3)

`drivers/mysql` now reports error 1062 (`ER_DUP_ENTRY`) as a unique violation, the way PostgreSQL and SQLite already did: `database.UniqueViolation` is true for it and a handler that returns it answers 409 instead of 500. Code that expected a 500 for a duplicate entry on MySQL or MariaDB needs to expect 409.

### WebSocket subscriptions to a presence channel are refused when the store fails (from drivers/websocket v0.1.6)

`drivers/websocket` lists the members of a presence channel with `Subscription.Here` before it answers `subscribed`. When the presence store fails (Redis down, for example), the subscription is closed and the client gets an error frame with status 503, where it used to be subscribed with an empty member list. Clients should retry the subscription on that error. `broadcast.Subscription.Members` is deprecated for the same reason: use `Here(ctx, channel)`, which takes a context and reports store errors. `Members` keeps working until v2.

## New features worth adopting

Added in v0.41 and not required: `web.MapError[E]` maps an error type to a response in one place (see [Mapping errors by type](../http.md#mapping-errors-by-type)); `inertia.Define` and `vukem codegen:pages` type the props of Inertia pages; typed `html/template` views and `vukem view:check`; `vukem db:pull`, `migrate:check` and `migrate:diff`, `Schema.Rebuild` and `Column.Change` for SQLite; savepoints (`database.Nested`) and optimistic locking (`orm:"version"`); `vukem bench` and `bench:run`; `vukem upgrade`, `stub:publish` and the `db` console.

Added in v0.42 and not required: `vukem studio`, a browser for the project's SQL, MongoDB and Redis data (`contrib/studio`); the experimental Turso driver (`drivers/turso`); and a shared presence store for `drivers/redis`, so presence channels agree across instances.

Everything added during the BETA is listed in the [changelog](../../CHANGELOG.md): GraphQL with subscriptions, gRPC, WebSockets and broadcasting, the admin panel, the `/_vukem` dashboard, JWT and TOTP two-factor, Stripe billing, resumable uploads, S3, MySQL, templ and Inertia (React, Vue, Svelte) starters, typed API clients.

Apps that open Redis only when `REDIS_URL` is set (and keep their own glue that loads the configuration before `vukem.New`) can return `nil, vukem.ErrUseDefault` from `WithCacheStoreFunc`, `WithSessionStoreFunc` and `WithQueueDriverFunc` instead: the configured default store is used, and any other error still fails ([Redis](../subsystems.md#redis)). Return it only outside production, or a missing `REDIS_URL` there runs the app on per-process stores. Apps that set `QUEUE_CONNECTION=database` next to a `WithQueueDriverFunc` now have the function run at boot instead of on the first `app.Queue()` (its error fails the boot); the queue tables are created only when it returns `ErrUseDefault`.
