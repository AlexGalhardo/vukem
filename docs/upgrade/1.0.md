# Upgrading to v1.0

**Estimated effort:** low for apps on `v0.20`, medium from earlier `v0.x` releases. v1.0 freezes the API: after this upgrade, later `v1` releases follow the [stability policy](../stability.md).

## Before you start

- Go **1.27.2** or later (the minimum in every `go.mod`; it carries the `net/http` and `crypto/tls` security fixes).
- On your current version (`v0.21`–`v0.25`), run `go fix ./...` first: it rewrites uses of the deprecated aliases that v1.0 removes (see [Renamed or removed APIs](#renamed-or-removed-apis-public-api-review)).
- Upgrade the CLI and every Vukem module to the same version:

```sh
go install github.com/AlexGalhardo/vukem/cmd/vukem@v1.0.0
go get github.com/AlexGalhardo/vukem@v1.0.0
go get github.com/AlexGalhardo/vukem/drivers/postgres@v1.0.0 # and each driver or contrib module you use
go mod tidy
```

## Required changes

### Multipart forms with method override (from v0.19)

`middleware.MethodOverride` no longer parses multipart bodies to find `_method`, so uploads can stream. Put the override in the form's action URL:

```html
<!-- before -->
<form method="post" enctype="multipart/form-data" action="/posts/1">
  <input type="hidden" name="_method" value="PUT">
<!-- after -->
<form method="post" enctype="multipart/form-data" action="/posts/1?_method=PUT">
```

URL-encoded forms keep working with the hidden field.

### gRPC reflection in production (from v0.20)

`GRPC_REFLECTION_IN_PRODUCTION` is now `GRPC_INSECURE_REFLECTION_IN_PRODUCTION`, and the constant `grpc.ReflectionInProductionEnv` is `grpc.InsecureReflectionInProductionEnv`.

### i18n.Middleware returns an error

`i18n.Middleware(bundle, cfg)` returns `(func(http.Handler) http.Handler, error)` instead of panicking when `cfg` fails `MiddlewareConfig.Validate`. Apps that wire it by hand handle the error; `vukem.DefaultMiddleware`, `DefaultMiddlewareWith` and `APIMiddlewareWith` are unchanged.

```go
// before
r.Use(i18n.Middleware(bundle, i18n.MiddlewareConfig{}))
// after
locale, err := i18n.Middleware(bundle, i18n.MiddlewareConfig{})
if err != nil {
	return err
}
r.Use(locale)
```

Calls to `i18n.NewMiddleware`, which already returned the error, keep compiling; `go fix ./...` rewrites them to `i18n.Middleware`.

### Email verification needs the login (from v0.27)

The `install:auth` scaffold used to verify the address when the signed link was opened signed out. If someone signed up first with another person's address, the owner clicking that link verified the squatter's account (with the squatter's password). The link now needs the login of the account it verifies: signed out, it leads to `/login`, and the login comes back to the link (the intended URL) and verifies it; another signed-in account still gets 403. Apps generated before v0.27.0 keep the old behaviour until they re-run `vukem install:auth --force` (review the diff in a branch) or port it by hand:

```go
// routes/auth.go: before
r.Get("/email/verify/{id}", h.Verify).Name("verification.verify").Use(acc.Signer.Middleware())
// after
r.Get("/email/verify/{id}", h.Verify).Name("verification.verify").Use(required)
```

In `app/controllers/account/verification.go`, `Verify` takes the user from `auth.User[models.User](c, "web")` instead of loading it by id, answers 403 when `u.ID` differs from the `{id}` parameter, redirects an already verified user to `/dashboard`, checks the signature itself with `h.a.Signer.Verify(c.Request())` (on `signed.ErrExpired` it flashes the new `auth.verification_expired` message, added to `app/accounts/lang/*/auth.json`, and redirects to `/email/verify`; otherwise it logs `url.signature_invalid` and answers 403), then checks `email_hash` and calls `h.a.VerifyEmail(c.Context(), &u, c.Session().ID())` followed by `h.a.Web.RefreshSession(c)`. With `--social`, the callback in `routes/social.go` redirects to `web.SafeRedirect(c.Request(), target, "/dashboard")` with the `auth.IntendedKey` it pulls from the session, like `Login`. Generated tests that open the link signed out and expect a redirect to `/login` followed by a verified account now log in first (see `TestRegisterAndVerifyEmail` in a fresh scaffold).

### Renamed or removed APIs (public API review)

The pre-freeze API reviews are recorded in [docs/api/review.md](../api/review.md) (with the full `apidiff` report next to it) and [docs/v1-api-review.md](../v1-api-review.md). Identifiers renamed in `v0.21` kept a deprecated alias marked `//go:fix inline` for five releases; v1.0 removes the aliases, so run `go fix ./...` before the upgrade or rename by hand.

| Before | After | Migration |
| --- | --- | --- |
| `orm.BeforeCreater`, `orm.AfterCreater` | `orm.BeforeCreator`, `orm.AfterCreator` | `go fix ./...` on `v0.21`–`v0.25`, or rename by hand (aliases removed in v1.0) |
| `mail.WithAttachments` | `mail.Attachable` | `go fix ./...` on `v0.21`–`v0.25`, or rename by hand (alias removed in v1.0) |
| `stripe.Client.Do` (`contrib/stripe`) | `stripe.Client.Call` | `go fix ./...` on core `v0.25` with a `contrib/stripe` that still has `Do`, or rename by hand (same arguments; `Call` also takes `RequestOption`s) |
| `i18n.NewMiddleware` | `i18n.Middleware` | deprecated alias, still compiles; `go fix ./...` rewrites it (see [above](#i18nmiddleware-returns-an-error)) |
| `hash.DefaultArgon2` (variable) | `hash.DefaultArgon2Params()` | replace by hand; it returns a copy, so `p := hash.DefaultArgon2Params(); p.Memory = …; hash.Argon2id(p)` |
| `dbtest.Author`, `dbtest.Book`, `dbtest.Meta`, `dbtest.Tag` | unexported | none for drivers: `dbtest.Run` is unchanged |

## New features worth adopting

Everything added during the BETA is listed in the [changelog](../../CHANGELOG.md): GraphQL with subscriptions, gRPC, WebSockets and broadcasting, the admin panel, the `/_vukem` dashboard, JWT and TOTP two-factor, Stripe billing, resumable uploads, S3, MySQL, templ and Inertia (React, Vue, Svelte) starters, typed API clients.

Apps that open Redis only when `REDIS_URL` is set (and keep their own glue that loads the configuration before `vukem.New`) can return `nil, vukem.ErrUseDefault` from `WithCacheStoreFunc`, `WithSessionStoreFunc` and `WithQueueDriverFunc` instead: the configured default store is used, and any other error still fails ([Redis](../subsystems.md#redis)). Return it only outside production, or a missing `REDIS_URL` there runs the app on per-process stores. Apps that set `QUEUE_CONNECTION=database` next to a `WithQueueDriverFunc` now have the function run at boot instead of on the first `app.Queue()` (its error fails the boot); the queue tables are created only when it returns `ErrUseDefault`.

## Generated code

Apps created by earlier `vukem new` versions keep working. To pick up new scaffolding (Vite + Tailwind CSS v4, `boost:install`, `install:auth --2fa`, `install:billing`, `install:admin`), run the installer in a branch and review its diff.

## Verification

```sh
vukem migrate
go vet ./...
go test ./...
```
